# 02: Первая тревога в новом формате — «Remnawave не отвечает» при «🚀 Подключиться»

**What to build:** Клиент нажимает «🚀 Подключиться», панель отвечает 502 (или таймаут, или «токен не принят»). В «🚨 Тревоги» приходит тревога из четырёх частей: что случилось (настоящая причина с HTTP-кодом / временем ожидания / числом попыток), где заметили (действие + модуль и функция), чем грозит, куда смотреть (2–4 причины для ЭТОГО вида сбоя, по убыванию вероятности). Клиент видит прежний короткий экран. Сквозной путь, на котором держатся остальные задачи: спецификация `../spec.md`, раздел «Тревога: из чего собирается». Причины — из `../research/prichiny-sboev.md` (раздел Remnawave).

Expand: новый вызов тревоги (ключ, функция-источник как объект, ошибка, подстановки) добавляется РЯДОМ со старым (ключ + готовый текст); старые вызовы не трогаем.

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] Ошибки Remnawave несут вид сбоя (конечный список: нет соединения, не дождались ответа, 5xx, 429, токен не принят, ответ не той формы, неожиданная версия и т. п.) и подробности; перевод ошибок библиотеки дополнен, а не заменён.
- [ ] В `alerts/` — описание тревоги `remnawave_unavailable` (заголовок, чем грозит, где заметили) и тексты для каждого вида сбоя Remnawave (описание + причины с проверками). Без IP и секретов.
- [ ] Новый вызов тревоги собирает текст из четырёх частей; место в коде берётся из переданной функции (модуль.имя).
- [ ] Всё из ошибки маскируется и экранируется; итог не длиннее предела Telegram — урезаются подробности, части не теряются (тест с огромной ошибкой).
- [ ] Бот не стартует, если у описания тревоги нет заголовка/«чем грозит»/«где заметили» или у вида сбоя нет описания или причин (тест загрузки).
- [ ] Тест через бота целиком: при 502 и при «токен не принят» тревога содержит настоящую причину, функцию обработчика и РАЗНЫЕ причины; клиент видит прежний экран; кнопка «Поставить плашку» под тревогой осталась.
- [ ] Склейка повторов по ключу работает как раньше.
