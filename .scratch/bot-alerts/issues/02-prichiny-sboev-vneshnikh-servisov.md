# Вероятные причины сбоев внешних сервисов

Type: research
Status: resolved

## Question

Что на самом деле стоит за каждым видом сбоя, который видит бот, при нашем устройстве серверов? Какие причины самые вероятные и что проверить для каждой?

Виды сбоев:
- **Remnawave**: не дождались ответа, не удалось соединиться, HTTP 5xx / 502 / 503 / 429, 401 / 403 (токен), 404, ответ не той формы, неожиданная версия панели, неверная подпись вебхука, нода потеряла связь;
- **Platega**: не отвечает, отказ создать платёж, отказ проверки (ключи), чужой или подделанный вебхук, спор через банк;
- **Telegram**: не создалась тема, клиент заблокировал бота, рассылка прервана;
- **бэкапы**: нет свежей копии, копия не ушла в Telegram, бот не может прочитать папку.

Для каждого вида — 2–4 причины по убыванию вероятности и что проверить: где смотреть (кабинет, панель, сервер) и какую команду запустить, если она нужна. Только чтение. Подключаться к серверам нельзя.

Источники: `ops/` (как развёрнуты панель, туннель, бот), `.scratch/archive/vpn-bot-rework` (задача 22 — бэкап и обновление панели), код `bot/src/tsproxy/integrations/`, документация Remnawave, Platega, Telegram Bot API.

Результат — `.scratch/bot-alerts/research/prichiny-sboev.md`.

## Answer

Ответ — в [`research/prichiny-sboev.md`](../research/prichiny-sboev.md). Для каждого вида сбоя там 2–4 причины, от самой вероятной, с пометками «репо / документация / вывод» и командами только для чтения.

Коротко:
- **Remnawave.** Бот ходит в панель через Cloudflare. Код ответа подсказывает, где поломка: 502 — упала панель за туннелем, 530/1033 — упал сам туннель, обрыв соединения — сеть или DNS сервера. 401/403 — прежде всего права или перевыпуск токена; 403 может прислать и Cloudflare. «Не та форма» — обычно обновили панель, а SDK закреплён на 3.4.5. Единичная «неверная подпись» — скорее посторонний запрос на открытый адрес, а тревога на каждое событие — разошлись секреты. Нода чаще всего «пропадает» из-за перезапуска, файрвола или смены IP.
- **Platega.** Отказ создать платёж, скорее всего, из-за обязательного по документации поля `metadata`, которое бот не шлёт. Отказ проверки — ключи (401 `Auth:GEN_1001`). «Подделка» — чаще всего посторонний запрос на открытый адрес или сменённые ключи.
- **Telegram.** Тема не создаётся — у бота забрали право «Управление темами» или выключили темы. Рассылка обрывается сразу — скорее всего, удалили исходное сообщение для копии.
- **Бэкапы.** Бот не может прочитать папку — скорее всего, права сбросились на 700: скрипт в репозитории расходится с серверным. Копия не уходит в Telegram — устаревший токен в `telegram.env`. Сбой до ловушки ошибок в скрипте проходит молча.

Попутно: при сбое токена или версии панели на запуске бот перезапускается по кругу без тревоги.
