# Обёртка Remnawave

Type: task
Status: resolved
Blocked by: 01

## Что сделать

`integrations/remnawave.py` поверх `remnawave-api` под панель 3.4.5: найти/создать `tg_<id>` (409 → найти), поставить срок «до X», включить/выключить, лимит устройств 3 и трафик, устройства (список, удаление), первое подключение, ссылка подписки и её перевыпуск, состояние нод. Таймауты и повторы. Проверка версии панели при старте.
**Защита нынешних клиентов:** обёртка отказывается менять аккаунт без префикса `tg_` (боевой режим) или вне squad `test` с префиксом `dev_` (разработка); в списках видит только свои аккаунты.

## Готово, когда

- Тесты на подделке.
- Ручной прогон на панели: `dev_`-аккаунт создан, продлён, выключен, удалён; аккаунты вне `test` не изменились (сверка до и после).

Решения: задачи 11, 15; спецификация §Главные правила (в `../vpn-bot-rework/issues/`). Спецификация — `../spec.md`.

### 2026-10-24 — обёртка написана (агент), проверки на живой панели не было

**Библиотека.** Взяли `remnawave-api==3.4.5` (версия закреплена точно). Она заявлена для панели 3.4.4 и новее и работает асинхронно. Модели библиотеки сверены с контрактом панели на теге 3.4.5: пользователь, устройства, ноды, squad'ы, версия. Расхождений, которые нам мешают, нет, поэтому решение задачи 09 остаётся в силе. Что выяснилось при чтении исходников:
- сетевые ошибки и таймауты библиотека **не** превращает в свои ошибки (вопреки `research/remnawave.md` §5): наружу выходит исключение `httpx` как есть, обёртка ловит его сама;
- «имя уже занято» приходит как HTTP **400** с кодом `A019`, а не как 409; «уже выключен» и «уже включён» — тоже 400, с кодами `A029` и `A030`;
- библиотека требует `httpx<0.28` и ровно `rapid-api-client==0.6.0`. Если другой пакет потребует новый `httpx`, будет конфликт. Тогда заменим библиотеку своим клиентом на `httpx`; для остального кода интерфейс не изменится.

**Что сделано.**
- `src/tsproxy/integrations/remnawave_types.py` — модели `ProxyAccount`, `Device`, `Node`; ошибки `AccountNotFound`, `ForeignAccountError`, `RemnawaveUnavailable`, `RemnawaveAuthError`, `RemnawaveRejected`, `RemnawaveResponseError`, `UnexpectedPanelVersion`, `OperationNotAllowed`; интерфейс `RemnawaveClient`; защита `AccountGuard`.
- `src/tsproxy/integrations/remnawave.py` — настоящий клиент `RemnawaveApiClient`. Шлёт свой User-Agent (иначе Cloudflare блокирует), таймаут 10 с. До 3 попыток делает только для чтения и для «поставить срок до X» или лимиты. Создание, выключение, перевыпуск ссылки и удаление не повторяет. Проверка версии: если основная версия панели не 3, бот отказывается запускаться; другая 3.x даёт только предупреждение.
- `src/tsproxy/integrations/fakes.py` — `FakeRemnawave` для тестов следующих задач, с той же защитой.
- Аккаунт клиента везде ищется по Telegram ID: в боевом режиме имя `tg_<id>`, в разработке `dev_<id>`. Перед любым изменением обёртка заново читает аккаунт из панели и проверяет его. В боевом режиме проходят только `tg_<цифры>`, в разработке — только `dev_<цифры>` в squad `test`. Иначе `ForeignAccountError`, и изменяющий запрос не отправляется. Списки показывают только свои аккаунты. Удалять аккаунт можно только в режиме разработки.
- Новые аккаунты в разработке попадают в squad `test`. В боевом режиме — в squad, имя которого передаётся при создании клиента. Предполагаем `Default-Squad` из наброска; это нужно подтвердить при подключении бота.
- Тесты: в `tests/integrations/` их 103. Они проверяют запросы и разбор ответов на образцах из контракта 3.4.5, повторы и ошибки, защиту для каждого изменяющего действия и подделку.
- `scripts/check_remnawave_dev.py` — сценарий ручной проверки. Сначала снимает слепок всех аккаунтов. Затем создаёт `dev_999000001` в squad `test`, продлевает его, ставит лимиты, перевыпускает ссылку, выключает и удаляет. В конце снова снимает слепок и сверяет, что чужие аккаунты не изменились. **Скрипт не запускался.**

Осталось: ручная проверка на настоящей панели (аккаунт dev_ в squad test), делает ведущий агент. Нужны `RUN_MODE=dev` и токен разработки в `.env`, затем `uv run python scripts/check_remnawave_dev.py --yes`.
