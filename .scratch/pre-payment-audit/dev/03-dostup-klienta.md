## Находки

Разобрано по коду (`bot/callbacks.py`, `services/trial.py`, `integrations/remnawave.py` с `AccountGuard`, профиль, устройства, перевыпуск ссылки). 🔴 нет.

Почему лазеек нет:
- Кнопки несут только «что открыть»; чей клиент — всегда `from_user.id` нажавшего. Кривые данные отбрасывает разбор (pydantic): обработчик не находится, клиент видит «кнопка устарела, нажмите /start».
- Каждое действие с панелью сначала перечитывает аккаунт `tg_<telegram_id>` и сверяет имя (`_own_account`); аккаунты с другими именами бот не трогает и не видит в списках. Удаление аккаунтов в бою запрещено в самой обёртке.
- Пробный — одна атомарная отметка `UPDATE … WHERE trial_granted_at IS NULL`; оплатившему не выдаётся, даже если панель лежит; аккаунт с подпиской (без лимита трафика) пробным не перетирается. Новый аккаунт Telegram — новый пробный (так решил владелец).
- Устройство ищется только среди устройств нажавшего; «перевыпустить» без данных, двойное «Да» перевыпускает один раз.

Уже было в тестах: два одновременных «Попробовать», повторный пробный, пробный после оплаты, чужое устройство, чужая кнопка «Подключиться», двойной перевыпуск. **Добавлено** `bot/tests/bot/test_forged_buttons.py` (15 тестов, с контролем «настоящий тариф заказ создаёт»): мусор в данных кнопок, несуществующий тариф для СБП / звёзд / экрана тарифа, номер несуществующего и чужого заказа в «🔄 Проверить оплату» — ничего не создаётся, чужое не показывается, тревог нет.

### Сценарии для скрипта-кликера (задача 12)

1. /start → «🎁 Попробовать бесплатно» дважды быстро → один пробный, одна ссылка.
2. После пробного → «Попробовать» → «уже брали».
3. «📱 Мои устройства» → удалить устройство → список обновился; второе нажатие на ту же кнопку → «устройства нет».
4. «🔄 Перевыпустить ссылку» → «Да» дважды → ссылка сменилась один раз.
5. Старая кнопка из истории чата (после /start) → «кнопка устарела».
6. «💳 Тарифы» → тариф → «СБП» дважды → одна и та же ссылка (оплата выключена на проде — только на стенде).
