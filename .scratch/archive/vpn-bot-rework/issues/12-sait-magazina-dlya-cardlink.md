# Сайт магазина для Cardlink

Type: grilling
Status: resolved

## Question

Для модерации Cardlink магазину нужен домен и сайт с контактами, офертой, условиями возврата, политикой персональных данных и ценами. Домен `success_url` и `fail_url` должен совпадать с доменом магазина. Есть ли у нас сайт и домен, что на нём будет (заодно туда можно положить инструкции по подключению), кто готовит тексты оферты и политик, на какой домен регистрируем магазин в Cardlink.

## Answer

Решено с владельцем 2026-10-20.

- **Домен:** сайт и магазин Cardlink на `ts-proxy.com`, том же домене, что и панель (`panel.ts-proxy.com`). Агент рекомендовал отдельный домен, чтобы при блокировке витрины не пострадала инфраструктура. Владелец выбрал общий.
- **Название сервиса — TS Proxy.**
- **Состав сайта:** главная (о сервисе, преимущества, тарифы с ценами, как оплатить, «Открыть бота», контакты); инструкции для iOS, Android, Windows и macOS (на них ведёт кнопка «Инструкции» в боте); документы (оферта, условия возврата, политика ПДн); `/paid` и `/failed` — сюда Cardlink возвращает клиента, страница сама открывает бота.
- **Делает агент:** простой статический сайт (HTML/CSS), отдельный проект, не внутри бота. ~~Cloudflare Pages~~ → **раздаётся с нашего сервера напрямую, без прокси Cloudflare** (решение 2026-10-21 из-за замедления Cloudflare в России, задача «Сервер и деплой»).
- **Плашка при сбое:** если бот не отвечает, сайт показывает плашку «Извините, у нас неполадки». Для этого у бота нужен публичный адрес проверки состояния (`/health`), который сайт опрашивает.
- **Исполнитель в документах:** физлицо без статуса, без публичных персональных данных в документах — решение владельца. Владелец знает: от Cardlink анонимности нет (для вывода нужны паспорт РФ с пропиской и проверка лица, см. https://cardlink.link/reference/limits-and-verification), а регулярные продажи без статуса — налоговый риск. Переход в самозанятые меняет документы в паре строк.
- **Возвраты:** «просто передумал» не возвращаем (есть пробный период). Если VPN не работал по нашей вине и поддержка не помогла — возвращаем деньги за неиспользованные полные дни. Запрос на возврат клиент делает **явно**: кнопка «↩️ Вернуть деньги» в профиле → бот объясняет условия и показывает сумму за неиспользованные полные дни (считает сам) → клиент пишет причину → создаётся обращение с пометкой «↩️ ВОЗВРАТ» и уведомление в закреплённой теме «↩️ Возвраты» в общей группе администраторов. В теме обращения кнопки: «✅ Одобрить возврат» (бот напоминает сумму и номер платежа для возврата в кабинете Cardlink и после подтверждения отключает подписку) и «❌ Отказать» (бот просит причину и отправляет её клиенту).
- **Документы:** черновики оферты, условий возврата и политики ПДн готовит агент по принятым решениям. Данные исполнителя вписывает владелец, проверка юристом желательна.
- **Структура оферты (решено 2026-10-21, по образцу соглашения MilkSurf — https://telegra.ph/Polzovatelskoe-soglashenie-07-10-20; текст не копируем, пишем своими словами):**
  1. Формат лицензии на ПО для шифрования и маршрутизации интернет-трафика через удалённые серверы.
  2. Возврат — только в течение 30 дней с оплаты, при неустранимой технической проблеме на нашей стороне, пропорционально неиспользованным дням, **не чаще одного раза в полгода** на клиента.
  3. Нет возврата, если доступ к сервису ограничил интернет-провайдер или государственный орган.
  4. Запрещённое использование: незаконная деятельность, спам, вредоносное ПО, DDoS, сканирование портов, нарушение авторских прав, **перепродажа доступа**. Нарушение — отключение доступа без возврата.
  5. Клиент возмещает претензии третьих лиц, возникшие из-за его действий. Пункт об ответственности пользователя — как в `drafts/pozitsionirovanie.md`.
