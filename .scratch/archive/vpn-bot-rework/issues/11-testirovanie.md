# Тестирование

Type: grilling
Status: resolved
Blocked by: 09

## Question

Как проверяем, что всё работает без багов: автотесты (pytest) бизнес-логики с подменой Remnawave и Cardlink, проверка подписи postback, отдельный тестовый бот и тестовые аккаунты в панели, ручной чеклист перед выкаткой.

## Answer

Решено с владельцем 2026-10-21.

- **Пирамида тестов** — согласовано: правила (`domain/`) → сценарии с подделками Remnawave, Cardlink и Telegram → веб-сервер (подписи, кривые запросы, повторы) → с настоящей Remnawave (вручную) → ручной чеклист на тестовом боте. Агент сам дополняет идеи для тестов.
- **Настоящая Remnawave — боевая панель** (решение владельца): отдельный squad `test`, аккаунты с префиксом `dev_`. Защита в коде тестового клиента: отказываться трогать любой аккаунт без префикса `dev_` и вне squad'а `test`.
- **Управление временем** (замораживание и перемотка) — да. Работает только внутри нашего процесса Python; на часы Remnawave не влияет. События Remnawave со сроками в тестах имитируем вебхуками, а в проверке с настоящей панелью используем аккаунты с коротким сроком (минуты).
- **Критерий готовности** (формулировка владельца): тесты стоят на всех критических точках программы и не пускают код в продакшен, пока не пройдут. Каждое решение из задач 04, 05, 06, 10, 12, 16 покрыто хотя бы одним тестом; выкатка — только при зелёных автотестах и пройденном ручном чеклисте.
- **Ручной чеклист** — `docs/checklist.md`, по ролям: клиент (новый, пробный, покупка, продление и льготный период, устройства, поддержка, возврат, блокировка бота), администратор, группа администраторов, сбои, проверка настоящей оплаты после выкатки.
- **TDD** (красный → зелёный → рефакторинг) — обязательно для `domain/` и `services/`; для экранов не обязательно. Скил `/tdd`.
- **Хук `pre-commit`** (Python-аналог Husky): ruff + быстрые тесты перед каждым коммитом. Ставится первым шагом разработки, инструкция для нового компьютера — в README.
- **Тесты оплаты по слоям:** проверка подписи на примерах из документации (от сырой строки суммы) → сценарии с `FakeCardlink` (все случаи задачи «Жизненный цикл покупки», включая подделку и FAIL → SUCCESS) → веб-сервер (настоящие HTTP-запросы в формате платёжки) → ручной прогон на Mac в режиме `PAYMENTS_MODE=fake` со скриптом `simulate_payment.py` → настоящие деньги на сервере.
- С ЮKassa: оплата картами проверяется в **тестовом магазине** без денег; **СБП в тестовом магазине нет** — СБП проверяем только настоящим платежом скрытого тарифа.
- **Скрытый тариф «Тест — 15 ₽ / 1 день»**, виден только администраторам; первый настоящий платёж проверяет формат суммы, комиссию и подпись.

## Уточнение владельца (2026-10-24)

Отдельного тестового бота не заводим: переписываем рабочего бота (@username тот же), им сейчас никто не пользуется. Защита живых клиентов Remnawave остаётся прежней: в разработке — только squad `test` и префикс `dev_`, отдельный токен Remnawave для разработки. Git — пока локально, GitHub позже.
