## Что защищаем и от чего

- **Вход на сервер.** Кто зайдёт с правами root, получит всё: базу клиентов, ключи Reality, токены ботов. Защита: вход только по ключам, у каждого человека свой ключ, оповещение о каждом входе.
- **Лишние открытые порты.** Каждая программа, которая слушает интернет, — это возможная дыра. Защита: файрвол открывает только то, к чему подключаются клиенты.
- **Панель.** Через неё можно выдать себе подписку или удалить всех клиентов. Защита: панель не торчит в интернет, вход только через Cloudflare с проверкой почты.
- **Старые уязвимости.** Защита: автоматические обновления безопасности.
- **Поломка или потеря данных.** Защита: ежедневные зашифрованные бэкапы в Telegram, тревоги в Telegram.

## Правила работы (чтобы не потерять доступ)

1. Перед любым изменением SSH или файрвола держим **вторую открытую SSH-сессию**. Если новая настройка не пускает, через старую сессию откатываем.
2. Запасной вход — **консоль VNC в кабинете Axion** (экран сервера в браузере, работает даже при сломанном SSH). Пока владелец не проверит, что консоль открывается, **вход по паролю не выключаем**.
3. Для каждого шага ниже указан откат.
4. Секреты (пароли, токены, `.env`, закрытые ключи) не пишем в чат, Telegram и git.

## Шаг 1. Ключи и вход по SSH

**Как это работает.** SSH-ключ — пара файлов. **Закрытый** (`id_ed25519`) — как ключ от квартиры: лежит только у владельца, никому не передаётся. **Открытый** (`id_ed25519.pub`) — как замок: его можно отправить кому угодно, его ставят на сервер. Ушёл человек или украли ноутбук — снимаем только его замок, остальные не трогаем.

**Поэтому закрытые ключи в Telegram не отправляем** — ни свои, ни сгенерированные за сотрудника. Кто получит такой файл (чат взломают, телефон потеряют, участника добавят по ошибке), тот войдёт на сервер root-ом. Каждый сотрудник создаёт ключ **у себя** и присылает только `.pub`. Инструкция для сотрудников — в конце документа.

Что делает агент:
- [ ] 1.1. Владелец создаёт отдельный ключ для серверов TS Proxy (сейчас стоит рабочий ключ `a.tzarev@idem.agency` без пароля). Агент ставит его на оба сервера, проверяет вход, потом снимает рабочий ключ. На Mac — короткие имена: `ssh axion`, `ssh node2`.
- [ ] 1.2. Ставим открытые ключи сотрудников (каждый — с подписью имени), проверяем вход каждого.
- [ ] 1.3. **После шага 0 (консоль проверена)** выключаем вход по паролю. Настройки SSH:
  - `PasswordAuthentication no`, `KbdInteractiveAuthentication no` — пароль через SSH не принимается вообще, подбирать нечего;
  - `PermitRootLogin prohibit-password` — root входит только по ключу;
  - `MaxAuthTries 3`, `LoginGraceTime 30` — меньше попыток на одно подключение;
  - `X11Forwarding no`, `AllowAgentForwarding no` — выключаем то, чем не пользуемся.
  - Порт SSH оставляем **22**. Смена порта только уменьшает мусор в журналах, а при входе по ключам подобрать всё равно нечего.
  - Откат: вернуть файл `/etc/ssh/sshd_config.d/10-tsproxy.conf` (удалить его) через вторую сессию или консоль.
- [ ] 1.4. **Оповещение о входе:** при каждом входе по SSH в тему «Тревоги» приходит «Вход на axion: root, ключ <имя>, с IP …». Чужой вход сразу виден.

**Решить владельцу:** все входят как `root` по своим ключам (просто, как сейчас) **или** у каждого своя учётная запись с `sudo` (видно, кто что делал, но агенту нужен будет отдельный доступ). Рекомендация: **`root` по ключам + оповещения о входе** — для команды из 2–3 человек этого достаточно.

## Шаг 2. Файрвол

**Как это работает.** Файрвол (`ufw`) — список «кому можно постучаться в сервер снаружи». Всё, чего нет в списке, отбрасывается. Исходящие подключения (боты к Telegram, WARP, обновления) не ограничиваем.

**Основной сервер `89.251.22.48`** — открываем:

| Порт | Зачем |
|---|---|
| 22/tcp | SSH |
| 443/tcp | «Основной» (XHTTP Reality) |
| 8443/tcp | «Альтернативный 2» (TCP Reality) |
| 2053/tcp | «Альтернативный 1 (gRPC)» — см. «Найдено при переезде» |
| 2083/tcp | «Альтернативный 3» |
| 8080/tcp, 2052/tcp | «Резерв» и «Резерв 2» через Cloudflare. Можно открыть **только для адресов Cloudflare** — тогда напрямую к ним не подключиться |
| 2333/tcp, 6767/tcp+udp | rathole — **только если запускаем** (вопрос открыт) |

**Закрыто снаружи:**
- 2222 (управление нодой) — нужно только панели, а она на этом же сервере. Разрешаем только изнутри сервера (сети Docker).
- Панель (3000), страница подписки, база, Redis — работают только внутри сервера; наружу их выводит туннель Cloudflare, порт открывать не нужно.
- WARP (40000) — только `127.0.0.1`.
- Новый бот — только `127.0.0.1`; снаружи к нему ходят через туннель Cloudflare (см. шаг 6).

**Германия 2 `130.78.12.97`** — открываем: 22, 443, 8444 (адреса «Германия 2»), а **2222 — только для `89.251.22.48`** (панель). Сейчас управление нодой открыто всему интернету.

Подвох Docker: опубликованные порты контейнеров обходят `ufw`. Поэтому все контейнеры панели публикуются только на `127.0.0.1`, а после включения файрвола агент **проверяет снаружи** (сканом портов с Mac и через check-host.net), что открыто ровно то, что в таблице.

Откат: `ufw disable` из второй сессии или консоли.

## Шаг 3. Обновления и журналы

- [ ] **Автообновления безопасности** (`unattended-upgrades`): исправления устанавливаются сами каждую ночь. **Без автоматической перезагрузки** — если ей нужна перезагрузка, бот напишет в ежедневный отчёт, перезагружаем вместе в тихое время.
- [ ] **Версии программ закреплены**: панель `3.4.5`, нода `3.4.2` на обоих серверах. Сейчас на «Германии 2» стоит `latest` — при перезапуске нода может сама обновиться до версии, несовместимой с панелью. Обновляем только вручную: бэкап → обновление → проверка.
- [ ] **Размер журналов** ограничиваем 500 МБ (на Zomro системный журнал занимал 300 МБ памяти).
- [ ] **Файл подкачки**: 2 ГБ на основном, 1 ГБ на «Германии 2» — запас, если не хватит памяти.

## Шаг 4. Защита от подбора (`fail2ban`)

- [ ] Кто 5 раз за 10 минут не смог войти по SSH — блокировка IP на час; кого блокировали несколько раз — на неделю. При входе только по ключам подобрать нечего, но это убирает шум и нагрузку.

## Шаг 5. Программы — каждая со своими правами

Сейчас на Zomro оба старых бота работают от `root` в окнах tmux: если в боте найдут дыру, у взломщика будет весь сервер; после перезагрузки боты сами не поднимутся.

На новом сервере:
- [ ] Каждая программа — **отдельный пользователь** без пароля и без входа: `tsproxy` (новый бот), `vombot`, `furgpt`, `rathole`. Взломали `vombot` — доступны только его файлы.
- [ ] Каждая — **служба systemd**: сама стартует после перезагрузки, перезапускается после падения, журнал в одном месте.
- [ ] Ограничения служб: нельзя повысить права (`NoNewPrivileges`), система только для чтения (`ProtectSystem=strict`), писать можно только в свою папку (`ReadWritePaths`), свои временные файлы (`PrivateTmp`), нет доступа к домашним папкам.
- [ ] Файлы с секретами (`.env`, токены ботов, конфиг rathole) — права `600`, владелец — пользователь программы. На Zomro `/opt/remnawave/.env` был открыт на чтение всем (`644`).
- [ ] Docker доступен только `root`. Никого не добавляем в группу `docker` (это то же, что дать `root`).
- [ ] WARP — системная служба, слушает только `127.0.0.1:40000`.

## Инструкция для сотрудников (текст для Telegram)

> **Доступ к серверам TS Proxy — нужен ваш SSH-ключ**
>
> Закрытый ключ никому не отправляйте — ни сюда, ни в личку. Присылайте только файл, который заканчивается на `.pub`.
>
> **macOS / Linux** — в Терминале:
> `ssh-keygen -t ed25519 -C "имя-фамилия"`
> На вопрос о месте — Enter. Придумайте пароль на ключ (его спросят при входе; на Mac можно запомнить в Связке ключей).
> Затем: `cat ~/.ssh/id_ed25519.pub` — скопируйте строку целиком (начинается с `ssh-ed25519`) и пришлите сюда.
>
> **Windows** — в PowerShell те же команды; файл: `type $env:USERPROFILE\.ssh\id_ed25519.pub`.
>
> Когда ключ поставят, вход: `ssh root@<адрес сервера>`.
