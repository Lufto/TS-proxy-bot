Что появилось в `src/tsproxy/jobs/`:

- `backup.py` — `DatabaseBackup` (сервис бэкапа), `DocumentSender` (интерфейс «отправить файл в тему»: `async send_document(chat_id, thread_id, path, caption)`; настоящий на aiogram — в задаче 06), `Encryptor`, `BackupResult` и `run_daily_backup(backup)` — точка входа для планировщика. Боевая сборка: `DatabaseBackup.from_settings(settings, documents, alerter)`.
- `backup_files.py` — блокирующие шаги (вызываются только через `asyncio.to_thread`): копия SQLite через online backup API, `PRAGMA integrity_check`, gzip, раскладка по `daily/` и `monthly/` (права 600, папки 700, запись через временное имя), чистка ежедневных копий, разбор `DATABASE_URL`.
- `age.py` — `AgeEncryptor` (`age --encrypt --recipients-file <открытый ключ> --output <файл> <вход>`), `CommandRunner` и настоящий `SubprocessRunner` (`asyncio.create_subprocess_exec`, без оболочки, с ограничением времени 5 минут).
- `fakes.py` — подделки для тестов: `FakeDocumentSender`, `FakeCommandRunner` (запоминает команды и «шифрует» меткой).

**Как работает** (так же, как бэкап панели в `ops/remnawave-backup/`):
1. Копия живой базы без остановки бота: SQLite копирует её за один шаг, бот в режиме WAL продолжает писать, в копию попадают только завершённые транзакции.
2. Проверка целостности копии.
3. gzip + `age` открытым ключом из `BACKUP_AGE_RECIPIENTS` (по умолчанию `/etc/remnawave-backup/recipients.txt` — тот же ключ, что у панели, аудит R15). Незашифрованная копия живёт только во временной папке внутри `BACKUP_DIR` (права 700) и удаляется в любом случае.
4. `BACKUP_DIR/daily/tsproxy-ГГГГ-ММ-ДД.db.gz.age` и `BACKUP_DIR/monthly/tsproxy-ГГГГ-ММ.db.gz.age` (месячная перезаписывается каждый день → остаётся последняя за месяц). Дата в имени — по Москве. `BACKUP_DIR` по умолчанию `/var/backups/tsproxy`.
5. Отправка файла в «💾 Бэкапы» (`BACKUPS_THREAD_ID`). Файл больше 50 МБ (предел Telegram) не отправляется — тревога.
6. Ежедневные копии старше 14 дней (по дате в имени) удаляются; месячные и чужие файлы не трогаются никогда.

**Сбои.** Не получилась копия (база, диск, `age`) — запись в лог, тревога `bot_backup_failed` в «🚨 Тревоги», исключение летит дальше (его увидит сторож фоновых задач), старые копии не удаляются. Не ушло в Telegram — лог, тревога `bot_backup_not_sent`, локальная копия остаётся, чистка идёт как обычно, `run` не падает.

**Только SQLite.** Для другого `DATABASE_URL` (и для базы в памяти) конструктор `DatabaseBackup` бросает `BackupNotSupportedError` «бэкап пока умеет только SQLite». Чтобы ошибка случилась при запуске, а не ночью, **сборка приложения должна создавать `DatabaseBackup.from_settings(...)` при старте бота**.
