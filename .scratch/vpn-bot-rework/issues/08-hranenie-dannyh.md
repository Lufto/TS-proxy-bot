# Хранение данных

Type: grilling
Status: resolved
Blocked by: 04, 05

## Question

Какие данные бот хранит сам (клиенты, счета и платежи, факт использования пробного периода, действия администраторов) и где: SQLite или PostgreSQL, с ORM или без, как делать миграции и резервные копии.

## Answer

Решено с владельцем 2026-10-20.

1. **Срок подписки, её статус и подключения знает только Remnawave**, бот всегда спрашивает их там. В нашей базе хранится только то, чего в Remnawave нет: заказы, оплаты, пробный период, отправленные уведомления, действия администраторов.
2. **База — SQLite** на старте. Код пишем так, чтобы перейти на PostgreSQL сменой строки подключения.
3. **SQLAlchemy 2 (async) + Alembic** для миграций. Это не самый лёгкий вариант (легче — чистый SQL), но единственный, где одновременно просто перейти на PostgreSQL, есть надёжные миграции и поддерживается async. Аналоги хуже: у Tortoise ORM слабые миграции, Peewee не асинхронный.
4. **Четыре таблицы:**
   - **Клиенты** — Telegram ID, @username, имя, id VPN-аккаунта в Remnawave, начало пробного периода и число продлений, пометка «заблокировал бота», дата первого визита.
   - **Заказы** — (+ поле «до какой даты продлить», `grant_target_expire_at`, добавлено 2026-10-21 по аудиту) номер, клиент, тариф, цена и дни на момент заказа, статус (создан → оплачен → доступ выдан / не выдан / на ручной проверке), id и ссылка счёта Cardlink, фактически оплаченная сумма и время, число попыток выдачи.
   - **Уведомления** — кому, какое, когда отправлено (чтобы не дублировать).
   - ~~**Журнал администраторов**~~ → заменён общим **«Журналом событий»** (задача «Логи и мониторинг», 2026-10-21): важные события по клиентам, заказам и действиям администраторов, бессрочно.

   Телефоны, почты и данные карт не храним. **Если структуру понадобится расширить или изменить, сначала сообщаем владельцу и решаем вместе.**
5. **Срок хранения:** клиенты, заказы и журнал администраторов — бессрочно; уведомления — 90 дней.
6. **Резервные копии:** автоматически раз в сутки. Ежедневные копии храним 2 недели. Копия за последний день каждого месяца хранится бессрочно с понятным именем (например, `bot-2026-10.db`). Куда класть копии — решаем в задаче «Сервер и деплой».
7. **Клиент заблокировал бота:** ставим пометку, не шлём ему уведомления и рассылки, в статистике видно число таких клиентов. При новом `/start` пометка снимается.

> **Уточнение 2026-10-21 (задача 23):** из таблицы «Клиенты» убраны имя и @username; добавлена таблица обращений (связка с темой, статус, время, без текстов).
