# Защита SSH и доступ команды к серверу

Type: task
Status: open

## Question

Закрыть вход на сервер по паролю через SSH и устроить доступ так, чтобы владелец и второй сотрудник могли работать с сервером и восстановить доступ без владельца. Часть задачи «Сервер и деплой» (07, пункты «SSH только по ключу, файрвол, fail2ban, автообновления»), вынесена отдельно 2026-10-22.

HITL: каждое изменение на сервере — по «ок» владельца, как в задаче 22. Сначала проверяем запасной вход (консоль Zomro), только потом отключаем пароли.

## Как устроено (объяснено владельцу 2026-10-22)

- У каждого человека **свой** SSH-ключ; на сервере в `~/.ssh/authorized_keys` — их открытые половины («замки»). Ушёл человек / украли ноутбук — удаляем только его замок.
- Вход по паролю через SSH выключен; пароль `root` остаётся для **консоли VNC в кабинете Zomro** (не через SSH, из интернета не подобрать).
- Потеряли все ключи → кабинет Zomro → консоль → пароль `root` → новый замок. Забыли пароль `root` → смена пароля в кабинете Zomro.

## Что нужно от владельца

- [ ] Проверить в кабинете Zomro (VPS `212.43.146.106`): есть ли **консоль VNC** и открывается ли (экран `login:`); есть ли **смена пароля root**; включить **2FA** на вход в кабинет. Прислать скриншот страницы VPS.
- [ ] Знать пароль `root` (для консоли); если не знает — сменить в кабинете и сохранить.
- [ ] Завести **общее хранилище паролей** на двоих (Bitwarden или 1Password) и положить туда: вход в Zomro, пароль `root`, ключ расшифровки бэкапов, копию своего SSH-ключа.
- [ ] ⚠️ Ключ расшифровки бэкапов сейчас (2026-10-22) лежит у владельца в Telegram («Избранное»). **До подключения отправки бэкапов в Telegram** перенести его в хранилище паролей (или на бумагу) и удалить из Telegram — иначе копии и ключ в одном аккаунте. Включить облачный пароль Telegram.
- [ ] Сотрудник создаёт свой SSH-ключ (`ssh-keygen -t ed25519`) и присылает **только** `.pub` (его можно в чат).
- [ ] (по желанию) Пароль на свой SSH-ключ (`ssh-keygen -p -f ~/.ssh/id_ed25519`), Mac запомнит его в Связке ключей.

## Что делает агент (по шагам, после проверки консоли)

- [ ] Добавить замок сотрудника, проверить его вход.
- [ ] Выключить вход по паролю в SSH (`PasswordAuthentication no`, `KbdInteractiveAuthentication no`, `PermitRootLogin prohibit-password`), не закрывая текущую сессию; проверить вход ключом из новой сессии; откат — вернуть файл настроек.
- [ ] Файрвол (`ufw`): сначала опись всех слушающих портов (SSH 22, VPN 443/8443/8080 TCP, нода 2222, AmneziaWG 51820/udp и 51821, Minecraft, frp/rathole, боты), владелец утверждает список, потом включение.
- [ ] `fail2ban` для SSH.
- [ ] Автообновления безопасности (`unattended-upgrades`).
- [ ] Права `600` на `/opt/remnawave/.env` (сейчас `644`).
- [ ] Записать итог в `research/` или сюда (без секретов).
