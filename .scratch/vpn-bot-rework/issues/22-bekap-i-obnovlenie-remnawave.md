# Бэкап и обновление Remnawave (агент на сервере)

Type: task
Status: open

## Question

Сделать полный бэкап панели Remnawave, убедиться, что из него можно восстановить подключения клиентов, и обновить панель 2.7.4 → 2.8.1 → 3.x. Работу на сервере делает агент по SSH; **каждое действие агент сначала описывает, владелец отвечает «ок»**, только потом агент выполняет. Связанные задачи: «Обновление панели Remnawave» (чеклист `docs/remnawave-upgrade.md`), «Страница подписки Remnawave».

Как начать в новой сессии: открыть этот файл и написать агенту «работаем по задаче 22».

---

## Правила работы агента на сервере

1. **Сначала только смотрим.** Пока не закончена разведка, никаких изменений.
2. **Каждое изменяющее действие** агент описывает простыми словами (что, зачем, что будет при ошибке, как откатить) и показывает точную команду. Выполняет **только после «ок»** владельца.
3. **Секреты не выводим в чат**: содержимое `.env`, пароли, ключи, токены. Если нужно проверить значение — проверяем наличие/длину, не печатая.
4. **Бэкап — до любых изменений**, и он должен лежать **не только на сервере** (скачиваем на Mac).
5. Обновляем **по одному шагу**, после каждого — проверка. Не прошла — останавливаемся и откатываемся.
6. Работаем **в спокойное время**, клиентов заранее предупреждаем о техработах.

## Что нужно от владельца перед началом

**Данные для подключения (не секретные, можно написать в чат):**
- [ ] IP-адрес или имя сервера;
- [ ] порт SSH (если не 22);
- [ ] имя пользователя для входа (`root` или другой);
- [ ] если пользователь не `root` — работает ли у него `sudo` без пароля.

**Пароль от сервера в чат не присылать.** Вместо этого — SSH-ключ (шаг 0): агент будет подключаться с твоего Mac по ключу, который лежит у тебя.

**Разрешения в Claude Code:** агент будет запускать команды `ssh` и `scp` с твоего Mac. Каждую команду Claude Code покажет и спросит разрешения — это и есть твоё «ок».

**Время:** 1,5–3 часа на всё (с проверочным восстановлением), лучше вечером или ночью.

## План

### Шаг 0. SSH-ключ (делает владелец, ~5 минут, один раз)
- [ ] На Mac: `ssh-keygen -t ed25519 -C "tsproxy-admin"` (на вопросы — Enter; пароль на ключ можно задать).
- [ ] Отправить ключ на сервер: `ssh-copy-id -p <порт> <пользователь>@<сервер>` — один раз ввести пароль от сервера (в своём терминале, не в чате).
- [ ] Проверить вход без пароля: `ssh -p <порт> <пользователь>@<сервер>`.
- Вход по паролю пока **не отключаем** — это сделаем позже, в задаче «Сервер и деплой».

### Шаг 1. Разведка (только чтение)
- [ ] ОС и ресурсы: `lsb_release -a`, `df -h`, `free -h`.
- [ ] Как ставилась панель: `ls -la /opt/remnawave`, `ls /opt`, следы скрипта-установщика.
- [ ] Контейнеры: `docker ps --format "table {{.Names}}\t{{.Image}}\t{{.Ports}}"`, тег образа backend.
- [ ] Где база (контейнер PostgreSQL, его имя и том), где Redis/Valkey.
- [ ] Чем открыта панель наружу (Caddy/Nginx/контейнер установщика), какие домены, домен ссылок подписки.
- [ ] Есть ли ноды на этом же сервере и на других.
- [ ] Итог разведки агент записывает в этот файл (без секретов) и дописывает точные команды в шаги 2–6.

### Шаг 2. Полный бэкап
- [ ] Дамп базы PostgreSQL панели (`pg_dump` из контейнера базы) в файл с датой.
- [ ] Копии: `.env`, `docker-compose.yml`, `notifications-config.yml` (если есть), конфиг веб-сервера, папка установщика (если установка скриптом).
- [ ] Если ноды на других серверах — их `.env` / `docker-compose.yml`.
- [ ] Всё в один архив, **скачать на Mac** (например, `~/Backups/remnawave/2026-10-XX/`), проверить размер и что архив открывается.
- [ ] Записать: число пользователей и нод, версию панели — для сверки после.

### Шаг 3. Проверка восстановления (рекомендуется)
- [ ] Развернуть бэкап **на той же версии 2.7.4** во временной среде (локально в Docker на Mac или на временном сервере).
- [ ] Убедиться: пользователи на месте, их число совпадает, ссылки подписки те же, ключи Reality на месте.
- [ ] Удалить временную среду.
- Если пропускаем этот шаг — владелец явно принимает риск «бэкап может не развернуться».

### Шаг 4. Обновление 2.7.4 → 2.8.1
- [ ] Предупредить клиентов о техработах.
- [ ] Свежий дамп базы прямо перед обновлением.
- [ ] Обновление по `docs/remnawave-upgrade.md` (раздел «Шаг 1»), проверка логов, версии, пользователей, нод, VPN у тестового аккаунта.

### Шаг 5. Обновление 2.8.1 → 3.x
- [ ] Свежий дамп базы.
- [ ] `JWT_AUTH_SECRET` → `APP_SECRET` (значение то же), точная версия образа вместо `:3`.
- [ ] Обновление по `docs/remnawave-upgrade.md` (раздел «Шаг 2»), проверка.
- [ ] Ноды — после панели.

### Шаг 6. Проверка и настройки под бота
- [ ] Подключение тестового аккаунта, ссылки подписки, число пользователей совпадает.
- [ ] Токен бота к API работает (агент повторяет проверку связи).
- [ ] Домен ссылок подписки — не за прокси Cloudflare; инбаунд `vless_ws` без шифрования — решить; HWID-лимит 3; `EXPIRATION_NOTIFICATIONS=[-24, -1]`.

### Откат (если что-то пошло не так)
- [ ] Остановить панель, вернуть прежние `docker-compose.yml` и `.env`, восстановить базу из дампа, запустить прежнюю версию.
- [ ] Проверить, что клиенты подключаются.
