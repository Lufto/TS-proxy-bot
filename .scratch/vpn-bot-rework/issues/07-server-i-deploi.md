# Сервер и деплой

Type: grilling
Status: claimed

## Question

Как бот живёт на сервере без Docker: какой сервер и ОС, есть ли домен и HTTPS (нужен для postback от Cardlink и вебхуков Remnawave), стоит ли там уже nginx (например, для панели), как запускать и перезапускать бота (systemd), как выкатывать обновления, polling или webhook для Telegram.

## Черновик решений (2026-10-21, обсуждение продолжается)

- **Бот на том же сервере, что и панель** (Ubuntu, 2 ядра, ~4,8 ГБ памяти, свободно ~2,2 ГБ). К API панели и вебхукам Remnawave — напрямую внутри сервера, минуя Cloudflare.
- Панель, вероятно, ставилась скриптом-установщиком — проверить при разведке. Вход на сервер сейчас по паролю — перейти на SSH-ключи.
- **Служба systemd `tsproxy.service`** от отдельного пользователя `tsproxy`, автоперезапуск, `.env` с правами 600.
- **Деплой:** приватный репозиторий на GitHub + `deploy.sh` (pull → зависимости → бэкап базы → миграции → перезапуск → `/health`).
- **Резервные копии:** зашифрованные, на сервере **и** в теме «💾 Бэкапы» группы администраторов **и** в облачном хранилище (R2 или B2).
- **Безопасность:** вход только по ключу, файрвол, fail2ban, автообновления безопасности.
- **Адрес бота:** `bot.ts-proxy.com` через Cloudflare → веб-сервер панели → FastAPI на `127.0.0.1:8080` — для webhook Telegram.
- **Cloudflare и блокировки в РФ** (решено 2026-10-21): Cloudflare в России частично замедляют. Поэтому то, к чему обращаются из России, — **мимо прокси Cloudflare** (запись «DNS only», серое облако; домен остаётся на DNS Cloudflare):
  - **уведомления ЮKassa** — `pay.ts-proxy.com` напрямую на сервер, свой бесплатный сертификат (Let's Encrypt), файрвол пускает только IP ЮKassa; страховка — фоновая проверка неоплаченных платежей;
  - **сайт** `ts-proxy.com` — раздаётся с нашего сервера напрямую (вместо Cloudflare Pages — меняет решение задачи «Сайт магазина для Cardlink»);
  - **ссылки подписки** — проверить при обновлении панели, стоит ли их домен за Cloudflare; если да — вынести на адрес без прокси Cloudflare.
  - Минус: настоящий IP сервера становится виден (он и так известен через ноды).
- **Панель:** прямой доступ по IP закрыт полностью; вход только через `panel.ts-proxy.com` + **Cloudflare Access** (код на почту). Резервные копии базы и `.env` панели — как у бота.
- **Сервер один** (бот, панель, сайт, нода) — риск принят на старте.
- **Кто настраивает** — открытый вопрос. План — `docs/server-setup.md`.
