# API ЮKassa и Telegram Stars

Type: research
Status: open

## Question

Факты, на которых строится модуль оплаты:

**ЮKassa (API v3):**
- создание платежа для бота: `POST /v3/payments`, подтверждение redirect, ключ идемпотентности, `metadata` (номер нашего заказа), `capture`, способы оплаты СБП и карты, `return_url` (можно ли сразу в Telegram-бота);
- сколько живёт неоплаченный платёж (`pending`), можно ли переиспользовать ссылку, отменяется ли он сам;
- уведомления (HTTP notifications): события, формат, **как проверять подлинность** (список IP ЮKassa, перезапрос `GET /v3/payments/{id}`), повторы при не-200;
- особенности для **самозанятых**: нужен ли объект `receipt`, как чеки попадают в «Мой налог», ограничения API для НПД (например, автоплатежи, возвраты);
- возвраты (`POST /v3/refunds`), автоплатежи (сохранение способа оплаты) — что доступно самозанятому;
- тестовый магазин, тестовые карты и СБП;
- официальный Python SDK `yookassa` — актуальность, async, качество; или свой тонкий клиент на `httpx`.

**Telegram Stars:**
- как бот продаёт цифровую услугу за Stars (`sendInvoice` с валютой `XTR`, `pre_checkout_query`, `successful_payment`), подписки (`createInvoiceLink` с `subscription_period`), возвраты (`refundStarPayment`);
- курс Stars к рублю для покупателя и для продавца, комиссии, сколько реально получает продавец;
- **как выводить деньги** (Fragment, TON, минимальная сумма, задержка вывода, требуется ли проверка личности), работает ли это для гражданина РФ, налоги;
- актуальность правила «цифровые товары в ботах — только за Stars» на 2026 год и как его применяют к ботам, принимающим внешнюю оплату.
