# TS Proxy: выжимка решений и план

Состояние на 2026-10-21. Подробности каждого решения — в задачах `issues/`, карта — `map.md`, действия владельца — `owner-todo.md`.

---

## 1. Что решено

### Продукт
- **TS Proxy — прокси-сервис с шифрованием трафика.** Везде «прокси», слово «VPN» не используем. Не рекламируем доступ к заблокированным ресурсам (ст. 14.3 КоАП).
- Один клиент Telegram = один прокси-аккаунт `tg_<id>` в Remnawave. Покупка продлевает срок.
- **Тарифы:** 1 мес — 150 ₽, 3 — 405 ₽, 6 — 765 ₽, 12 — 1476 ₽ (скидки считаются сами). 30/90/180/365 дней. До 3 устройств. Скорость не ограничиваем.
- **Пробный период:** кнопкой, один раз; 7 дней и 7 ГБ. Не подключался — 5 продлений по 3 дня (до 22 дней) и прощальное сообщение. Подключался — напоминания за день и за час, без продлений.
- **Платная подписка:** напоминания за день и за час; затем **льготный период 3 дня** (прокси работает, напоминание каждые сутки); продление в льготный период — от момента оплаты (льготные дни — подарок); потом отключение без удаления аккаунта.
- **Приложения:** Happ — основное, v2RayTun — запасное. Протокол VLESS.

### Оплата и налоги
- **ЮKassa** (СБП + карты), владелец — **самозанятый**. Telegram Stars на старте не делаем. Cardlink и другие — в запасе.
- Цена — только из файла тарифов. Платёж живёт 1 час и переиспользуется. Каждый заказ засчитывается **ровно один раз**; в заказе заранее записано «до какой даты продлить».
- Оплату засчитываем только после **перезапроса статуса в ЮKassa**; уведомления приходят на `pay.ts-proxy.com` (мимо Cloudflare), плюс фоновая проверка неоплаченных платежей.
- Сбой Remnawave после оплаты: повторы каждую минуту 30 минут, затем раз в 10 минут до суток, тревога администраторам.
- **Чеки в «Мой налог» ЮKassa не делает**: на старте — вручную по подсказке бота, автоматизация — позже. Порядок — уточнить у бухгалтера.
- Возвраты: по кнопке, в течение 30 дней, за неиспользованные дни, не чаще раза в полгода, не при блокировке провайдером или государством; решает администратор.
- Риск правила Telegram о Stars принят; заводим запасной канал связи с клиентами.

### Бот
- Экраны: меню (одно сообщение меняется), пробный, тарифы и оплата, профиль (статус словами, срок по МСК, устройства «N из 3»), **«Мои устройства» с удалением**, «Подключиться» (страница подписки), «Скопировать ссылку», инструкции, поддержка, «О сервисе». Команды `/start`, `/profile`, `/buy`, `/support`.
- Тексты — `content/texts.yaml`, тексты админки — `content/admin_texts.yaml`, тарифы — `content/tariffs.yaml`.
- **Поддержка через бота:** любое сообщение — обращение; группа администраторов с темами (обращение = тема; «Оплаты», «Тревоги», «Возвраты», «Бэкапы» закреплены); ответы от «Поддержки», заметки `//`, «Беру», быстрые ответы, частые вопросы, напоминание о забытом обращении. Переписка хранится 3 года, файлы — только `file_id`.
- **Админка (2 администратора):** уведомления, поиск клиента, ручная выдача и продление, статистика, рассылка, сброс пробного и устройств, компенсация при падении ноды, перевыпуск ссылки подписки, перенос подписки на другой аккаунт с подтверждением платежа.

### Архитектура и код
- Python 3.13, `uv`, aiogram 3, FastAPI в одном процессе; SQLite через SQLAlchemy + Alembic; свой клиент ЮKassa на `httpx`; `remnawave-api` за своей обёрткой.
- Слои: `bot` / `services` / `domain` / `integrations` / `db` / `web` / `jobs` / `content`. Правила кода — `docs/python-rules.md`.
- Webhook Telegram везде (локально — туннель cloudflared и тестовый бот), с `secret_token`.
- События подписки — вебхуки Remnawave + сверка каждые 5–10 минут.
- **База:** клиенты, заказы, уведомления, журнал событий (бессрочно), обращения и переписка. Изменения структуры — только с согласия владельца.
- **Тесты:** TDD для правил и сценариев, подделки Remnawave/ЮKassa/Telegram, хук `pre-commit`, тестовый магазин ЮKassa, ручной чеклист `docs/checklist.md`, скрытый тариф 15 ₽.
- **Логи:** важные события — бессрочно в журнале событий, обычные — 30 дней; тревоги в группу; UptimeRobot + `/health`; отчёт в 10:00 МСК.

### Инфраструктура
- Один сервер (Ubuntu, 2 ядра, 4,8 ГБ): панель, бот, сайт, нода. Риск принят.
- Бот — служба `tsproxy` от отдельного пользователя; деплой — приватный GitHub + `deploy.sh`.
- Адреса: `bot.` — через Cloudflare; `pay.` и сайт `ts-proxy.com` — «DNS only»; панель — только `panel.ts-proxy.com` + Cloudflare Access, прямой доступ по IP закрыт.
- Резервные копии бота и панели — зашифрованные, на сервере + в Telegram + в облаке.
- SSH только по ключу, файрвол, fail2ban, автообновления.
- Панель обновляется 2.7.4 → 3.x; страница подписки разворачивается после.
- Токены бота и Remnawave перевыпускаются при запуске нового бота.

## 3. Когда начинаем писать код

**Как только владелец скажет «всё обсудили».** Ждать ответа ЮKassa и обновления панели для старта не нужно:
- первые этапы (каркас, правила, база, экраны) от них не зависят;
- тестовый магазин ЮKassa открывается **без ИНН и договора** — оплату можно разрабатывать сразу;
- обновлённая панель 3.x нужна к этапу работы с настоящей Remnawave.

Сначала агент собирает из карты спецификацию и нарезает задачи разработки (`/to-tickets`), владелец их смотрит. Примерный порядок:

1. Каркас проекта: `uv`, структура пакета `tsproxy`, ruff, `pre-commit`, `.env.example`, загрузка текстов и тарифов.
2. Правила (`domain`) — сроки, пробный и льготный период, пропорции, возвраты — через TDD.
3. База: таблицы и миграции.
4. Клиент Remnawave 3.x (нужна обновлённая панель) и защита тестов `dev_`/`test`.
5. Экраны бота: меню, пробный период, профиль, устройства, инструкции.
6. Оплата: клиент ЮKassa (тестовый магазин), жизненный цикл заказа, уведомления, фоновая проверка.
7. Фоновые задачи и вебхуки Remnawave: напоминания, льготный период, продления пробного, сверка.
8. Поддержка через бота и группа администраторов.
9. Админка: поиск, выдача, статистика, рассылка, компенсации, возвраты, перевыпуск ссылки.
10. Логи, `/health`, тревоги, ежедневный отчёт.
11. Сайт и документы.
12. Проверка безопасности кода (`/security-review`), ручной чеклист, деплой.
