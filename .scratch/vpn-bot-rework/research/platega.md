## Политика ПДн

- Оператор — «сервис Platega.io», без юрлица.
- У контрагентов (мерчантов) обрабатывают **ФИО, должность, паспортные данные**, контакты.
- Данные граждан РФ — **в базах на территории РФ**. Хранение **не менее 5 лет** после прекращения отношений.
- Передача третьим лицам без согласия — в случаях, предусмотренных законом, «например, по запросу правоохранительных органов».

## Выводы

1. **Как физлицо без статуса по оферте подключиться нельзя** — нужен ИП или юрлицо. Самозанятые не упомянуты. Уточнить у менеджера, не делают ли исключений.
2. **Штраф 10 000 ₽ за каждый проигранный чарджбэк** при цене тарифа 150 ₽ — один спорный клиент съедает выручку с 66 месячных подписок. Нужны доказательства оказания услуги и аккуратная работа с возвратами.
3. **Нельзя пользоваться одним кабинетом вдвоём** — владельцам нужно решить, кто один входит в кабинет.
4. Страница `/paid` с переадресацией в бота — уточнить у менеджера, не считается ли это «подменой адресов перенаправления трафика» (штраф 100% оборота).
5. Плюсы: российское право и суд (есть хоть какая-то правовая защита), ежедневные выплаты, VPN-проекты у них, судя по партнёрству с Bedolaga, есть.

## Разбор по запросу владельца (2026-10-26): отзывы, оферта, данные, путь денег

### API (по сторонним SDK, официальной документации публично нет)

`Platega.SDK` (NuGet, C#) и `aioplatega` (PyPI) — библиотеки сторонних авторов, не самой Platega. Из описания `Platega.SDK` видно устройство API:

- Базовый адрес `https://app.platega.io/`. Аутентификация — заголовки `X-MerchantId` и `X-Secret`.
- `CreateTransaction`: `PaymentMethod`, `PaymentDetails` (сумма, валюта), `Description`, `ReturnUrl`, `FailedUrl`, `Payload`. В ответе — `TransactionId`, `Redirect` (куда вести клиента), `Status`, `ExpiresIn`.
- `GetTransactionStatus`, вебхук с `CallbackPayload` (`Id`, `Amount`, `Status`, `Payload`); статусы `Confirmed` / `Canceled`; заголовки те же; повтор до 3 раз, пока обработчик не ответит 200.
- Способы оплаты: `SbpQr` = 2, **`CardsRub` = 10**, **`CardAcquiring` = 11**, `InternationalAcquiring` = 12, `Cryptocurrency` = 13.
- `GetRate` (`CurrencyFrom`/`CurrencyTo`, в примерах RUB→USDT) и `GetConversions` — **в API встроена конвертация в USDT**.
- **Методов возврата (refund) и выплаты (payout) в SDK нет.**

**[вывод]** Два отдельных способа для рублёвых карт — «CardsRub» и «CardAcquiring» — подтверждают догадку о P2P: при настоящем эквайринге второй способ был бы не нужен. Возвраты и вывод денег через API недоступны — только руками в кабинете или через менеджера.

### Порядок работы с деньгами

1. Бот создаёт транзакцию → получает `Redirect` → клиент платит по этой ссылке или QR.
2. Деньги попадают **не на счёт владельца**, а на сторону Platega (при P2P — на карту частного лица). Владелец их в этот момент не контролирует.
3. Вебхук `Confirmed` → бот выдаёт доступ. Сумма копится на внутреннем балансе кабинета, возможна конвертация в USDT.
4. Вывод — заявкой в кабинете (в API метода нет), по отзывам раз в день и не по выходным, иногда с задержкой конвертации.
5. Комиссия удерживается из поступлений (оферта 4.5). По оферте остаток могут заблокировать «по усмотрению Компании» (4.4), удержать при нарушении (3.5), оштрафовать на 10 000 ₽ за чарджбэк и на 100% оборота за «подмену перенаправления трафика».

Главное: **между оплатой клиента и деньгами владельца стоит сторона без лицензии и без названного юрлица**, и правила вывода задаёт она.

### Создание аккаунта

Регистрация по e-mail (по отзывам — «нужна только почта», «паспортные данные не нужны»), подтверждение владения сайтом, подключение через менеджера (@platega_connect_manager), условия согласуются индивидуально. Полноценная работа — только после проверки сведений и заключения договора (оферта). Срок подключения по отзывам 1–3 дня. Один кабинет — один человек (3.5). KYC на входе нет, но оферта и 115-ФЗ дают право запросить документы в любой момент, в том числе при выводе.

### Хранение данных

- Оператор ПДн — «сервис Platega.io», **юрлицо не названо**. Предъявить претензию по ПДн некому.
- У мерчанта берут **ФИО, должность, паспортные данные**, контакты.

## Полный текст оферты, прочитан с сайта 2026-10-26

Прочитано агентом в браузере (страница рендерится скриптом, в исходном коде текста нет): https://platega.io/ru/public-offer. Документ называется «Правила пользования сервисами Platega.io». **Даты редакции и номера версии нет.**

### Главное: самозанятый по оферте клиентом быть не может

«**Клиент: физическое лицо, зарегистрированное в качестве индивидуального предпринимателя, или юридическое лицо**». «ТСП — юридическое лицо или индивидуальный предприниматель». Самозанятый без ИП не предусмотрен ни одним пунктом. Подтверждено повторно (было и в версии от 21.10).

### Новое по сравнению с разбором 21.10: п. 4.7 «Конвертация валют»

Появился пункт, которого в прежнем тексте не было:
- конвертация — «по курсу, установленному Провайдером и/или соответствующим Партнёром на момент проведения операции»;
- курс «может отличаться от официальных курсов, устанавливаемых Центральным банком РФ, иными центральными банками, платёжными системами, банками, биржами»;
- «итоговая сумма операции после конвертации определяется исходя из курса, фактически применённого».

Это юридическое прикрытие скрытой комиссии на курсе, о которой пишет чат Bedolaga (+3–4% к рапире, «маржа Рапиры + Platega ≈ 5% от реального курса»). Оспорить курс по такому пункту нельзя: согласие считается данным фактом проведения операции.

### Ответственность: полностью асимметрична

Обязанности Провайдера (5.2): «ограничиваются информационно-технологическим обеспечением приема к оплате… **в объеме, предусмотренном договором между Провайдером и ТСП**». Провайдер не сторона сделки и не отвечает за её исполнение. Плюс 5.1: «Сервис не несёт ответственности за возможные ограничения, блокировки или отмены операций, осуществляемые Провайдерами и/или Эмитентами».

**Чего в оферте нет вообще:** сроков выплат, минимальной суммы вывода, размера комиссии (только «по Договору»), гарантий доступности сервиса, порядка возврата денег клиентам, судьбы остатка при расторжении по инициативе любой стороны, порядка расторжения клиентом, упоминания чеков.

Прав у Провайдера (5.3): менять функциональность без уведомления, останавливать работу, прекращать доступ при нарушениях. Обязанностей перед мерчантом — ни одной измеримой.

### Деньги: за что удерживают и штрафуют

- **3.5** — передача/совместное использование аккаунта: без уведомления заблокировать кабинет и операции, «заблокировать денежные средства, находящиеся на балансе, **без права их вывода**», отказать в обслуживании; удержать средства «в целях покрытия возможных убытков, штрафов, возвратов (chargeback) и иных финансовых рисков». **Срок удержания определяет сама Компания.**
- **4.3** — лимиты на платежи устанавливаются и меняются в одностороннем порядке.
- **4.4** — холд «по усмотрению Компании»: блокируется вывод и/или приём средств. Ни оснований, ни сроков.
- **4.5** — комиссия удерживается в одностороннем порядке из поступлений.
- **Штраф 100% оборота** за «некорректные коды отслеживания, подмену адресов перенаправления трафика, искусственное увеличение (подлив) трафика либо иные… способы обхода установленных правил привлечения трафика» + приостановка выплат + блокировка аккаунта «без возможности восстановления, в том числе с удержанием остатка» + расторжение. Факт нарушения фиксирует сама Компания актом или электронным уведомлением.
- **Чарджбеки:** оспаривает сам клиент; за каждый неоспоренный или проигранный — штраф **10 000 ₽**.
- **Доказательства оказания услуги** хранить не менее 6 месяцев и выдавать по запросу Общества, Провайдера или Эмитента.

### Нюансы юридической техники (важные)

1. **Юрлица нет.** Сторона называется «Platega.io», «Провайдер», «Общество», «Компания». Ни названия, ни ИНН, ни адреса. При этом подсудность (7.3) — «по месту нахождения Провайдера», а претензии (7.1) — «по адресу местонахождения Провайдера». **Адрес в документе не указан нигде**, то есть формально неизвестно, куда писать и в какой суд идти.
2. **Штрафы налагает недоговорённая сторона.** В разделе «Термины» определены Оператор, Партнер, Платежная система, Пользователь, Перевод, Сервисы, ТСП, Клиент. «Общество», «Компания», «Процессор», «Эмитент», «Получатель» не определены — а штрафы 100% оборота и 10 000 ₽ налагает именно «Общество».
3. **Это не договор.** П. 3.4: полноценное использование — только «после завершения проверки… а также после заключения Договора с Компанией». Все денежные условия (комиссия, холд, сроки выплат) живут в индивидуальном Договоре, которого публично нет. Оферта — лишь минимум обязательств.
4. **Нет даты редакции и версии**, а п. 9.3 позволяет менять Правила, и продолжение пользования = согласие. Доказать, какую редакцию принимал, невозможно.
5. **П. 9.1:** согласие с Правилами наступает от самого входа на сайт и перехода по ссылкам.
6. **Внутреннее противоречие по крипте.** В запрещённых категориях — «**любая деятельность, связанная с криптовалютами**». При этом сам сервис принимает оплату в BTC/USDT/GRAM и выплачивает мерчантам в USDT. То есть любой клиент, получающий выплаты в USDT, формально нарушает запрет — удобное основание применить п. 3.5 или штраф к кому угодно.
7. **П. 11.3 (переадресация).** Наша страница `ts-proxy.com/paid`, которая перебрасывает клиента в бота, формально похожа на «подмену адресов перенаправления трафика» — пункт со штрафом 100% оборота.
8. **Запрещённые категории:** азартные игры, ставки, аккаунты соцсетей, 18+, пирамиды, лотереи, крипта, кредитные брокеры, мошеннические схемы, «недобросовестное отношение к плательщикам и невыполнение обязательств перед ними», «любая иная деятельность, запрещённая на территории РФ». **VPN и прокси прямо не названы.**
9. Применимое право — РФ (9.2). Это единственный плюс по сравнению с Pally (Лондон).

### Вывод по рискам

Худшая конструкция из возможных: **все деньги лежат на балансе у стороны, которую нельзя назвать и которой нельзя предъявить претензию**, при этом она вправе в одностороннем порядке менять лимиты, ставить холд без оснований и сроков, определять курс конвертации и штрафовать на 100% оборота по собственному акту. Реальные условия — в невидимом индивидуальном договоре. Для нашего проекта вопрос закрыт ещё раньше: **по оферте самозанятый не может быть клиентом**.

## Документация API (docs.platega.io, прочитана 2026-10-30)

Официальная документация теперь есть (`https://docs.platega.io/llms.txt` — индекс). Главное для бота:

- База `https://app.platega.io/`, заголовки `X-MerchantId` и `X-Secret`.
- **Создание платежа:** `POST /transaction/process` с `paymentMethod` (2 — СБП QR, 3 — ЕРИП, 11 — карты, 12 — международные, 13 — крипта, 14 — SberPay), `paymentDetails {amount, currency}`, `description`, `return`, `failedUrl`, `payload`, `orderId`, `metadata {userId, userName}`. Ответ: `transactionId`, `redirect`, `status`, `expiresIn` (пример 15 минут), `usdtRate`. Вариант `POST /v2/transaction/process` — клиент сам выбирает способ. **P2P в списке способов нет** (у сторонних SDK раньше был `CardsRub` = 10 — в официальной доке его нет).
- **`metadata.userId`** «для магазинов отдельных категорий» обязателен, без него «отключает антифрод и может привести к отключению магазина» — передавать Telegram ID всегда.
- **Срок жизни ссылки ~15 минут** — у нас счёт живёт час (задача 04). Нужно согласовать.
- **Статусы:** `PENDING`, `CONFIRMED`, `CANCELED`, `CHARGEBACKED`, плюс в описании колбэков `PARTIALLY_REFUNDED`, `DISPUTED` (деньги зарезервированы).
- **Вебхук без подписи:** подлинность — только по заголовку `X-Secret` (тот же ключ, что у нас). **[вывод]** Как и в нашем решении для Cardlink: вебхук не доверять, каждый `CONFIRMED` перепроверять запросом `GET /transaction/{id}`. Повторы 3–4 раза за 30 минут, потом только вручную из кабинета — нужна фоновая сверка (она уже есть в задаче 14).
- **Возвраты через API есть:** полный `POST /transaction/{id}/cancel`, частичный `POST /transaction/{id}/cancel-partial` с `Idempotency-Key` (не для всех платежей — проверять `cancel-supported`). Списываются **с USDT-баланса**; могут уйти на ручную проверку. Частичный возврат подходит под наши «возвраты за неиспользованные дни».
- **Подписки (автосписание по СБП)** есть — на будущее, если включим автопродление.
- **Вывод через API** (Payout, подпись HMAC) — есть, на карту или криптокошелёк.
- **Чеки, тестовый режим, лимиты сумм, юрлицо** — в документации не упоминаются.
- В ответе статуса есть `comission`, `amountUsdt`, `person`, `contactPhoneNumber`.
