# Карта: переработка VPN-бота

Labels: wayfinder:map

## Destination

Записанная и согласованная спецификация бота: архитектура кода, бизнес-логика связки «бот ↔ Remnawave ↔ Cardlink», тарифы, пробный период, админка, тексты, деплой и тесты. Дальше она режется на задачи реализации.

## Notes

- **Код не пишем**, пока владелец явно не скажет «всё обсудили». До этого меняются только `.scratch/`, `GLOSSARY.md` и `docs/adr/`.
- Текущий `bot.py` — это набросок, а не версия продукта. Приложение пишется заново на его основе, поэтому совместимость с ним не нужна.
- Три внешние системы: Telegram-бот (aiogram 3), панель Remnawave (`panel.ts-proxy.com`, Python SDK `remnawave`), платёжка Cardlink (`https://cardlink.link/api/v1/`).
- Язык общения и текстов — русский. Объяснять просто: владелец не силён в архитектуре Python.
- Для решений вызывать скилы `grilling` и `domain-modeling`, термины брать из `GLOSSARY.md`.
- Тарифы из оффера владельца: 1 мес — 150 ₽, 3 мес — 405 ₽ (−10%), 6 мес — 765 ₽ (−15%), 12 мес — 1476 ₽ (−18%). Скорость до 1 Гбит/с, до 3 устройств, пробный период 24 часа, поддержка администратора (@Lufto_L2, @nnonick).
- Секреты хранятся в `.env`, в git лежит `.env.example` с примером. Токены не перевыпускаем, бот остаётся тем же.
- Сервер и деплой обсуждаем в самом конце, перед выкаткой (задача «Сервер и деплой»). До этого считаем, что у бота будет публичный HTTPS-адрес для уведомлений от Cardlink и Remnawave.
- Пишем под актуальную Remnawave 3.x. У владельца есть полный доступ к панели и её серверу.
- **Напомнить владельцу**, когда снова дойдём до оплаты (реализация или тесты Cardlink): предложить подготовить письмо в поддержку Cardlink (задача 13) и чеклист обновления панели (задача 14).
- Любое изменение структуры базы (таблицы, поля) сначала согласуем с владельцем.
- Заметки по Cardlink для владельца лежат в `CARDLINK.md` в корне проекта.
- Git только локальный, удалённого репозитория пока нет.
- Бот работает на сервере владельца без Docker, деплой командами.

## Decisions so far

- Один клиент ↔ один VPN-аккаунт `tg_<telegram_id>`. Покупка только продлевает подписку.
- Тексты и названия кнопок лежат в отдельном файле, их правят руками в файле. Формат файла решается в задаче «Тексты, экраны и кнопки».
- [Детали Cardlink](issues/02-detali-cardlink.md): оплату подтверждает только подписанный postback, который перепроверяется через `bill/status`. Result URL задаётся в настройках магазина. Песочницы нет. Для магазина нужны модерация и сайт с офертой. Клиент Cardlink пишем свой.
- [Возможности Remnawave](issues/01-vozmozhnosti-remnawave.md): старый пакет `remnawave` с панелью 3.x несовместим, нужен `remnawave-api` под нашу версию. Лимит устройств задаётся каждому VPN-аккаунту, скорость отдельно не ограничивается (1 Гбит/с — канал сервера). Пробный период собирается из обычных полей. Есть вебхуки об окончании подписки.
- [Проверка связи с Remnawave](issues/03-proverka-svyazi-s-remnawave.md): токен рабочий, панель версии 2.7.4 — нужно обновление до 3.x. Перед панелью стоит Cloudflare, который блокирует стандартный User-Agent Python.
- [Жизненный цикл покупки](issues/04-zhiznennyi-tsikl-pokupki.md): цена только из файла тарифов; счёт живёт час и переиспользуется; любая подтверждённая оплата засчитывается ровно один раз; при сбое Remnawave — повторы 30 минут и тревога администраторам; оплата не на сумму тарифа пересчитывается пропорционально (+2 часа); только СБП; комиссию платим мы.
- [Хранение данных](issues/08-hranenie-dannyh.md): срок и статус подписки знает только Remnawave; своя база SQLite через SQLAlchemy + Alembic (переход на PostgreSQL — сменой строки); четыре таблицы — клиенты, заказы, уведомления, журнал администраторов; ежедневные копии 2 недели + месячные бессрочно.
- [Архитектура кода](issues/09-arhitektura-koda.md): слои bot / services / domain / integrations / db / web / jobs / content; один процесс; FastAPI; webhook Telegram везде (локально через туннель cloudflared); события подписки — вебхуки Remnawave плюс небольшой планировщик; обёртка над `remnawave-api`; `uv`, Python 3.13, ruff, подсказки типов; правила в `docs/python-rules.md`.
- [Тексты, экраны и кнопки](issues/10-teksty-ekrany-i-knopki.md): меню в одном сообщении; профиль простыми словами; главная кнопка «Подключиться» ведёт на страницу подписки; тексты в `content/texts.yaml`, тексты админки — в `content/admin_texts.yaml`; даты по Москве; скидки считаются сами; кнопки «Скопировать ссылку» и «Продлить» в напоминаниях; без «Мои устройства».
- [Пробный период](issues/05-probnyi-period.md): кнопкой, один раз; 7 дней и 7 ГБ; если клиент не подключался — 5 продлений по 3 дня (до 22 дней); льготный период только после платной подписки, 3 дня, проведённые в нём дни — подарок; уведомления за день и за час; лимит 3 устройства.
- [Функции админки](issues/06-funktsii-adminki.md): семь функций к запуску — уведомления, поиск клиента, ручная выдача, статистика, рассылка, сброс пробного периода и устройств, компенсация при сбое сервера. Администраторов двое.

## Not yet specified

- **Инструкции по подключению**: основной путь — страница подписки Remnawave (задача «Страница подписки Remnawave») и короткий текст в боте. Подробные инструкции, возможно, на сайте (задача «Сайт магазина для Cardlink»). Какие приложения рекомендовать для каждой платформы.
- **Налоги и чеки**: Cardlink чеки по 54-ФЗ не формирует. Под каким статусом продаём (самозанятый, ИП) и нужно ли выдавать чеки самим.
- **Логи и мониторинг**: как администратор узнаёт, что бот упал или оплата не прошла.

## Out of scope

- Несколько VPN-аккаунтов у одного клиента (купить «второе подключение» отдельной кнопкой и продлевать каждое отдельно). Это будущее расширение: сейчас правило «один клиент — один VPN-аккаунт».
- Docker (для бота; панель Remnawave и её страница подписки работают в своих контейнерах).
- «Пригласить друга» (реферальная программа) — будущая функция.
- Ограничение скорости для отдельного клиента: Remnawave так не умеет, «до 1 Гбит/с» — это скорость канала сервера.
