# План настройки сервера для бота

Черновик (2026-10-21). Бот ставится **на тот же сервер, что и панель Remnawave** (Ubuntu, 2 ядра, ~4,8 ГБ памяти). Кто выполняет — решается позже: владелец по этому плану или агент по SSH с подтверждением каждого важного шага. **Ничего на сервере не меняем без «да» владельца.** Точные команды допишем, когда узнаем, как ставилась панель.

---

## 0. Разведка (только смотрим, ничего не меняем)

- [ ] Версия ОС: `lsb_release -a`.
- [ ] Как ставилась панель: есть ли `/opt/remnawave`, какой там `docker-compose.yml`, следы скрипта-установщика (`remnawave-reverse-proxy`, `remnawave-scripts` и т.п.).
- [ ] Что слушает порты 80/443 (Caddy, Nginx, контейнер установщика): `sudo ss -tlnp`.
- [ ] На каком порту панель доступна изнутри сервера (для обращения бота к API по `127.0.0.1`).
- [ ] Состояние файрвола (`sudo ufw status`), fail2ban, автообновлений.
- [ ] Свободное место на диске: `df -h`.

## 1. Безопасность входа (осторожно: не потерять доступ)

- [ ] На Mac владельца создать SSH-ключ: `ssh-keygen -t ed25519`.
- [ ] Добавить ключ на сервер: `ssh-copy-id <пользователь>@<сервер>`.
- [ ] **Проверить вход по ключу в отдельном окне терминала**, не закрывая текущую сессию.
- [ ] Только после успешной проверки — отключить вход по паролю (`PasswordAuthentication no` в `/etc/ssh/sshd_config.d/`), перезапустить SSH, ещё раз проверить вход в новом окне.
- [ ] fail2ban для SSH.
- [ ] Автоматические обновления безопасности: `unattended-upgrades`.
- [ ] Файрвол (ufw): открыты только SSH, 80, 443 и порты нод/инбаундов (443, 8443, …). **Сначала разрешить SSH, потом включать** — иначе отрежем себе доступ.

## 2. Пользователь и окружение бота

- [ ] Системный пользователь `tsproxy` без пароля и без права входа по SSH.
- [ ] Папка `/opt/tsproxy`: код бота — `app/` (папка `bot/` репозитория), общий конфиг — `config/`, скрипты службы — `ops/` и `/var/lib/tsproxy` (база SQLite, резервные копии) — владелец `tsproxy`.
- [ ] Установить `uv` и Python 3.13 для пользователя `tsproxy`.
- [ ] Файл `/opt/tsproxy/.env` с секретами, права `600`, владелец `tsproxy`.

## 3. Код и деплой

- [ ] Приватный репозиторий на GitHub; на сервере — deploy-ключ только на чтение.
- [ ] `deploy.sh`: `git pull` → `uv sync --frozen` → резервная копия базы → `alembic upgrade head` → `systemctl restart tsproxy` → проверка `/health` → при ошибке — подсказка, как откатиться.

## 4. Служба systemd

- [ ] `tsproxy.service`: запуск от `tsproxy`, `Restart=always`, автозапуск при загрузке, логи в системный журнал.
- [ ] Хранение журнала 30 дней (`journald`).

## 5. Адрес бота и HTTPS

> ⚠️ Схема Cloudflare и адреса — **ждут решений по аудиту безопасности** (`.scratch/archive/vpn-bot-rework/research/security-audit.md`, R03, R09, R11). Ниже — текущий вариант из задачи «Сервер и деплой».

- [ ] `bot.ts-proxy.com` — webhook Telegram (проверка `secret_token` обязательна).
- [ ] Уведомления платёжки — на тот же `bot.ts-proxy.com/payments/notification` (отдельного `pay.ts-proxy.com` нет, решение владельца 2026-11-10). **Без фильтра по IP** (адреса платёжки меняются): приложение отбрасывает уведомления по неизвестным или уже оплаченным заказам и перепроверяет статус у платёжки (задача 21, п. 12).
- [ ] `ts-proxy.com` — сайт (Next, служба `tsproxy-web`) через туннель Cloudflare `pereezd`, как бот. Выкатка, откат и порядок первого запуска — `ops/tsproxy-web/README.md` (задача сайта 16).
- [ ] Бот обращается к API панели внутри сервера, минуя Cloudflare. Вебхуки Remnawave — на адрес бота, **доступный из Docker-контейнера панели** (не `127.0.0.1` внутри контейнера, а адрес хоста/сети Docker — уточнить при разведке).

## 6. Резервные копии базы

- [ ] Ежедневно: копия SQLite (безопасным способом, без остановки бота), **шифрование паролем**.
- [ ] Храним на сервере: ежедневные — 14 дней, копия за последний день месяца — бессрочно (`tsproxy-2026-10.db.age` и т.п.).
- [ ] **И** отправляем зашифрованный файл в закреплённую тему «💾 Бэкапы» группы администраторов.
- [ ] **И** кладём в облачное хранилище (Cloudflare R2 или Backblaze B2).
- [ ] Пароль от шифрования хранится у владельца отдельно (менеджер паролей), не на сервере в открытом виде рядом с копиями.
- [ ] Раз в месяц — проверка, что копия восстанавливается.

## 7. Мониторинг

- [ ] UptimeRobot: `https://bot.ts-proxy.com/health`, сайт, панель; уведомления в Telegram и на email.

## 8. Первый запуск

- [ ] Деплой, миграции, запуск службы, `/health` = ok.
- [ ] Webhook Telegram установлен на `https://bot.ts-proxy.com/...`.
- [ ] В кабинете Platega (Настройки → Callback URLs) адрес колбэков — `https://bot.ts-proxy.com/payments/notification`; в `.env` — `PAYMENTS_MODE=platega`, боевые `PLATEGA_MERCHANT_ID` / `PLATEGA_SECRET`, `PLATEGA_TEST_ACCOUNT=false`, `BOT_USERNAME`.
- [ ] Пройти раздел «После выкатки» ручного чеклиста (`docs/checklist.md`).
