# Правила Python-кода в этом проекте

Короткий ликбез: что делаем, почему и как это выглядит. Код пишется по этим правилам и по ним же проверяется на ревью.

---

## 1. Секреты только в `.env`

Токены, пароли и ключи не пишем в код. Код читает их из файла `.env`, а он не попадает в git. В git лежит `.env.example` с теми же ключами, но без значений.

```python
# ❌ токен виден всем, кто видит код
TOKEN = "8889627995:AAF..."

# ✅ config.py читает .env
class Settings(BaseSettings):
    bot_token: str
    remnawave_token: str
```

**Зачем:** код можно показать, отправить или выложить, а секреты при этом не утекут.

## 2. Не глотаем ошибки молча

`except Exception: pass` значит «что бы ни случилось, сделай вид, что всё хорошо». Ловим только ту ошибку, которую ожидаем, и что-то с ней делаем.

```python
# ❌ «нет аккаунта» и «панель упала» выглядят одинаково
try:
    user = await remnawave.get_user(...)
except Exception:
    pass

# ✅ разные ситуации — разная реакция
try:
    account = await remnawave.find_account(client_id)
except AccountNotFound:
    account = None                      # нормальная ситуация: аккаунта ещё нет
except RemnawaveUnavailable:
    await alert_admins("Remnawave недоступна")
    raise                               # пусть вызывающий код решит, что дальше
```

**Зачем:** проглоченная ошибка — это баг, который невозможно найти.

## 3. Зависимости передаём явно

**Контекст.** В наброске объект `remnawave` создаётся один раз наверху файла (глобально), и каждая функция просто берёт его оттуда. Получается, что функция тайно зависит от настоящей панели, и проверить её без настоящей панели нельзя.

Правильно — передать то, с чем функция работает, снаружи, при создании:

```python
# ❌ функция сама лезет в глобальный объект
remnawave = RemnawaveSDK(...)

async def extend(client_id, days):
    await remnawave.users.update_user(...)

# ✅ сервис получает Remnawave «на вход»
class SubscriptionService:
    def __init__(self, remnawave: RemnawaveClient):
        self.remnawave = remnawave

    async def extend(self, client_id: int, days: int) -> None:
        await self.remnawave.extend(client_id, days)
```

**Зачем:** в тесте вместо настоящей панели передаём подделку (`FakeRemnawave`), которая просто запоминает вызовы. Тест идёт за миллисекунды и не трогает живых клиентов. Это называется «внедрение зависимостей» (dependency injection). Во фронтенде то же самое — передать функцию через props, а не импортировать её глобально.

## 4. Бизнес-правила — отдельными чистыми функциями

«Чистая» функция получает данные и возвращает результат, ничего не трогая снаружи: ни базы, ни сети, ни Telegram. Все расчёты сроков, пропорций и цен — такие функции в `domain/`.

```python
# ✅ domain/subscription.py
def renewal_start(now: datetime, expires_at: datetime | None, grace_started_at: datetime | None) -> datetime:
    """От какой даты считать новый срок при покупке."""
    ...
```

**Зачем:** такую функцию проверяет тест в три строки: «если льготный период начался 10.11, а сейчас 12.11, должно получиться …». Именно здесь живут правила, в которых нельзя ошибиться.

## 5. Структурированные данные — через модели, а не словари

**Контекст.** В наброске есть функция `get_attr(obj, "expire_at", "expireAt")`, которая «угадывает», как называется поле. Так получается, когда непонятно, какие у объекта поля.

Правильно — описать форму данных заранее. `dataclass` для своих данных, `pydantic` для данных извне (ответы API, уведомления): он сам проверяет, что пришло то, что ожидалось.

```python
# ✅ форма данных описана один раз
@dataclass(frozen=True)
class Tariff:
    id: str
    title: str
    days: int
    price: Decimal
```

**Зачем:** редактор подсказывает поля, опечатка `tarif.dyas` ловится до запуска, а кривые данные от Cardlink отбрасываются сразу, на входе. Это аналог интерфейсов в TypeScript.

## 6. Деньги — `Decimal`, не `float`

Обычные дробные числа (`float`) хранятся в компьютере неточно: `0.1 + 0.2` даёт `0.30000000000000004`. Для денег это недопустимо: при пересчёте пропорций копейки начнут «плыть».

```python
# ❌
price = 405.0
# ✅
from decimal import Decimal
price = Decimal("405.00")
```

## 7. Время — всегда с часовым поясом, в UTC

`datetime.now()` без пояса вернёт местное время машины: на Mac — московское, на сервере — может быть UTC. Одна и та же программа посчитает сроки по-разному.

```python
# ❌
now = datetime.now()
# ✅ внутри всё в UTC, переводим в московское только при показе клиенту
now = datetime.now(UTC)
```

## 8. Подсказки типов везде

Пишем, что функция принимает и что возвращает.

```python
def paid_days(tariff: Tariff, paid: Decimal) -> int: ...
```

**Зачем:** читается как документация, а редактор и `ruff` ловят ошибки до запуска. Это как TypeScript поверх JavaScript.

## 9. Маленькие функции с одной задачей

Если функцию нельзя назвать без слова «и» («создать счёт **и** отправить сообщение **и** записать в базу»), её надо разделить. Ориентир — функция помещается на экран.

## 10. Не блокируем асинхронный код

Бот асинхронный: одна программа обслуживает всех клиентов по очереди, переключаясь, пока кто-то ждёт ответа сети. Если одна функция «заснёт» по-настоящему, бот замрёт **для всех**.

```python
# ❌ останавливают весь бот
time.sleep(5)
requests.get(url)

# ✅ «ждём, но отпускаем остальных»
await asyncio.sleep(5)
await http.get(url)          # httpx.AsyncClient
```

Во фронтенде то же самое: синхронный цикл на 5 секунд замораживает страницу, а `await fetch()` — нет.

## 11. `logging`, а не `print`

`print` просто пишет в консоль. `logging` пишет с уровнем (`info`, `warning`, `error`), временем и источником, и на сервере это сохраняется в журнал, где можно искать.

```python
logger = logging.getLogger(__name__)
logger.warning("Заказ %s: сумма не совпала с тарифом", order_id)
```

## 12. Явное лучше неявного

Если поведение зависит от настройки, она должна быть видна: строка в `.env`, параметр функции. Никакой «магии», которая сама угадывает, где мы запущены. Данным извне (кнопки Telegram, уведомления) не доверяем: цену всегда берём из `content/tariffs.yaml`, а не из кнопки.

## 13. Одинаковый стиль — автоматически

`ruff` форматирует код и ловит типичные ошибки. Его запуск входит в проверку перед коммитом, поэтому о пробелах и кавычках спорить не нужно.

## 14. Имена

- Код (функции, переменные, классы) — на английском. Комментарии и docstring — на русском.
- `snake_case` для функций и переменных (`find_account`), `PascalCase` для классов (`PurchaseService`), `UPPER_CASE` для констант (`GRACE_DAYS = 3`).
- Никаких «магических чисел» в коде: `timedelta(days=GRACE_DAYS)`, а не `timedelta(days=3)`.
- Термины берём из `GLOSSARY.md`: клиент — `Client`, заказ — `Order`, счёт — `Bill`, льготный период — `grace`.
