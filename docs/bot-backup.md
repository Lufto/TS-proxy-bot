# Бэкапы базы бота

Раз в сутки бот сам делает копию своей базы (заказы, оплаты, клиенты, журнал событий). Задача — `.scratch/tsproxy-bot/issues/23-bekapy-bazy-bota.md`, устроено так же, как бэкапы панели (`ops/remnawave-backup/`).

## Как это работает

1. В 04:30 МСК (через полчаса после бэкапа панели) бот снимает копию базы, **не останавливаясь**: клиенты в это время продолжают пользоваться ботом.
2. Проверяет, что копия целая (`PRAGMA integrity_check`).
3. Сжимает (gzip) и шифрует программой `age` **открытым ключом** — тем же, что у бэкапов панели. На сервере лежит только «замок»; «ключ» (секретный) — у владельца.
4. Кладёт на сервер:
   - `daily/tsproxy-ГГГГ-ММ-ДД.db.gz.age` — хранятся 2 недели (14 копий);
   - `monthly/tsproxy-ГГГГ-ММ.db.gz.age` — последняя копия каждого месяца, хранится всегда.
5. Отправляет файл в тему «💾 Бэкапы» группы администраторов.

Если копия не получилась — тревога в «🚨 Тревоги», старые копии при этом не удаляются. Если копия есть, но не ушла в Telegram, — тоже тревога, а копия остаётся на сервере.

## Настройки (`.env`)

| Ключ | По умолчанию | Что это |
|---|---|---|
| `BACKUP_DIR` | `/var/backups/tsproxy` | Папка с копиями (`daily/`, `monthly/`) |
| `BACKUP_AGE_RECIPIENTS` | `/etc/remnawave-backup/recipients.txt` | Файл открытого ключа `age` (общий с панелью) |

Тема для файлов — `BACKUPS_THREAD_ID`, для тревог — `ALERTS_THREAD_ID`. Бэкап умеет только SQLite: с другим `DATABASE_URL` бот не запустится и скажет, что бэкап для этой базы ещё не сделан.

## Как восстановить базу из копии

Нужен секретный ключ — `~/Backups/remnawave/backup-key.txt` на Mac владельца (тот же, что для панели).

1. Скачать нужную копию: из темы «💾 Бэкапы» или с сервера (`/var/backups/tsproxy/daily/` или `monthly/`).
2. Расшифровать и распаковать (на Mac):
   ```
   age -d -i ~/Backups/remnawave/backup-key.txt tsproxy-2026-10-24.db.gz.age | gunzip > tsproxy.db
   ```
3. Проверить, что база целая — должно напечатать `ok`:
   ```
   sqlite3 tsproxy.db "PRAGMA integrity_check"
   ```
4. Остановить бота на сервере (служба systemd из задачи «Сервер и деплой»).
5. Отложить текущую базу вместе со служебными файлами `-wal` и `-shm` — их нельзя оставлять рядом с новой базой:
   ```
   mv data/tsproxy.db data/tsproxy.db.broken
   mv data/tsproxy.db-wal data/tsproxy.db-wal.broken 2>/dev/null
   mv data/tsproxy.db-shm data/tsproxy.db-shm.broken 2>/dev/null
   ```
6. Положить восстановленную `tsproxy.db` на место `data/tsproxy.db`, владелец — пользователь бота, права 600:
   ```
   chown tsproxy:tsproxy data/tsproxy.db && chmod 600 data/tsproxy.db
   ```
7. Запустить бота и проверить `/health` и карточку любого клиента.

Всё, что произошло после времени копии (новые заказы и оплаты), в восстановленной базе отсутствует: сверить с платёжкой и журналом событий вручную.
