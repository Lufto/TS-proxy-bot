# Обновление панели Remnawave 2.7.4 → 3.x

Чеклист для владельца. Панель сейчас **2.7.4** (проверено 2026-10-20), цель — **актуальная 3.x** (на 2026-10-06 это 3.4.5). Обновляем **по шагам**: сначала до последней 2.x (2.8.1), потом до 3.x. Между шагами — проверка, что всё работает.

Источники: [релиз Panel v3.x.x](https://f.docs.rw/t/topic/354) (официальный форум Remnawave), [релиз Panel v2.8.1](https://f.docs.rw/t/topic/178), [инструменты бэкапа](https://docs.rw/awesome-remnawave#backup-restore), [issue о сломанном обновлении 2.8 → 3.2 через скрипт](https://github.com/eGamesAPI/remnawave-reverse-proxy/issues/162).

> ⚠️ Делать в спокойное время (ночью), заранее предупредив клиентов о техработах. Во время обновления подписки могут не обновляться несколько минут.

---

## 0. Узнать, как установлена панель

- [ ] Панель ставилась **по официальной инструкции docs.rw** (папка `/opt/remnawave`, файл `docker-compose.yml`) — идём по этому чеклисту.
- [ ] Панель ставилась **скриптом-установщиком** (например, `remnawave-reverse-proxy`, `remnawave-scripts`) — обновлять по документации этого скрипта. Известный баг: скрипт оставлял backend на теге `:2`, а ноду поднимал на `3.0.0`, и ноды переставали работать. **Перед обновлением проверить теги образов в `docker-compose.yml` руками.**

## 1. Резервная копия (обязательно)

- [ ] Полный бэкап **базы данных** панели (инструменты — [docs.rw/awesome-remnawave#backup-restore](https://docs.rw/awesome-remnawave#backup-restore)).
- [ ] Копия файла **`.env`** панели.
- [ ] Копия **`docker-compose.yml`** и, если есть, **`notifications-config.yml`**.
- [ ] Копии лежат **не на этом же сервере** (скачать к себе).
- [ ] Записать, сколько сейчас пользователей и нод в панели (для сверки после обновления).

## 2. Шаг 1: 2.7.4 → 2.8.1

Что меняется:
- В базе `userUuid` заменяется на `userId` в таблицах HWID-устройств и истории запросов подписки. **История запросов подписки очищается.** Если устройств больше 500 тысяч — таблица устройств очищается (у нас столько нет).
- Уведомления об окончании подписки теперь **выключены по умолчанию** и настраиваются заново (см. шаг 4).
- События `user.expires_in_72_hours` и подобные заменены одним `user.expiration`. Если у вас есть свой `notifications-config.yml` — **удалить из него старые ключи**, иначе панель не запустится.

Действия:
- [ ] В `docker-compose.yml` у сервиса `remnawave` тег образа — `remnawave/backend:2` (последняя 2.x = 2.8.1).
- [ ] Обновить: `cd /opt/remnawave && docker compose pull remnawave && docker compose down && docker compose up -d && docker compose logs -f`
- [ ] В логах нет ошибок, панель открывается, версия **2.8.1**.
- [ ] Пользователи и ноды на месте, ноды онлайн, VPN у тестового аккаунта работает.

## 3. Шаг 2: 2.8.1 → 3.x

Что меняется:
- Пользователи определяются числовым `id`, поле `uuid` удалено. Поиск по Telegram ID — через `GET /api/users/stream?telegramId=…`. Это ломает старого бота-набросок — **так и задумано, новый бот пишется под 3.x**.
- Настройки подписки `profileTitle`, `supportLink`, `happAnnounce`, `happRouting` и т.п. переехали в пользовательские заголовки ответа (`profile-title`, `support-url`, `announce`, `routing`) — миграция автоматическая, проверить после обновления.
- Панель **больше не сжимает ответы** — сжатие включается на reverse proxy (см. ниже).

Действия:
- [ ] В `.env` панели переименовать **`JWT_AUTH_SECRET` → `APP_SECRET`**, значение оставить тем же. Без этого после обновления не войти в панель (ошибка 403).
- [ ] (необязательно) Удалить из `.env`: `JWT_API_TOKENS_SECRET`, `SWAGGER_PATH`, `SCALAR_PATH`, `IS_DOCS_ENABLED`.
- [ ] В `docker-compose.yml` сменить тег: `image: remnawave/backend:3`.
- [ ] Обновить: `cd /opt/remnawave && docker compose pull remnawave && docker compose down && docker compose up -d && docker compose logs -f`
- [ ] В логах нет ошибок, панель открывается, версия **3.x**.
- [ ] **Сжатие на reverse proxy:** Caddy — добавить `encode` в каждый блок сайта; Nginx — `gzip on;` в каждый `server`. Если перед панелью Cloudflare — сжатие на прокси выключить, его делает Cloudflare.
- [ ] Пользователи на месте, их число совпадает с записанным в шаге 1.

## 4. Ноды

- [ ] Обновить **ноды** до 3.x **после** панели. Старые ноды работают с новой панелью, но **нода 3.3+ требует панель 3.3+**, поэтому порядок только такой: сначала панель, потом ноды.
- [ ] Все ноды онлайн, трафик идёт.

## 5. Проверка после обновления

- [ ] Ссылка подписки тестового аккаунта открывается в VPN-приложении, подключение работает.
- [ ] Заголовки подписки (название профиля, ссылка поддержки) — на месте.
- [ ] **API-токен бота работает**: агент повторяет проверку связи (`/api/system/metadata` — версия 3.x, `/api/internal-squads` — squad на месте). Права токенов мигрируют автоматически.
- [ ] Squad `test` существует (нужен для тестов бота).

## 6. Настройки под нового бота (можно сразу после обновления)

- [ ] **Домен ссылок подписки:** проверить, через какой домен панель выдаёт ссылки подписки и стоит ли он за прокси Cloudflare (оранжевое облако). Если да — перевести на адрес без прокси Cloudflare: из России Cloudflare замедляют, и приложения клиентов могут не обновлять подписку.
- [ ] **Инбаунд `vless_ws` (порт 8080) работает без шифрования** (`security: none`, найдено 2026-10-21). Проверить в разделе Hosts, выдаётся ли он клиентам и есть ли TLS на уровне хоста. Если не нужен — отключить; если нужен — включить TLS. Иначе трафик таких клиентов идёт открытым, а мы обещаем шифрование.

- [ ] **Уведомления об окончании** для вебхуков бота: в `.env` панели `EXPIRATION_NOTIFICATIONS_ENABLED=true` и `EXPIRATION_NOTIFICATIONS=[-24, -1]` (за сутки и за час до окончания — как решено в плане).
- [ ] **Вебхуки:** `WEBHOOK_ENABLED=true`, `WEBHOOK_URL=` адрес бота (появится при деплое), `WEBHOOK_SECRET_HEADER=` случайная строка ровно из 64 символов (её же получит бот).
- [ ] **Лимит устройств (HWID):** включить в Subscription → Settings → HWID, общий лимит — 3.
- [ ] Перезапустить панель после правки `.env`.

## Если что-то пошло не так

- [ ] Остановить панель, вернуть старый `docker-compose.yml` и `.env`, восстановить базу из бэкапа шага 1, поднять снова.
- [ ] Написать в чат агенту: что делали и что в логах (`docker compose logs remnawave --tail 200`).
