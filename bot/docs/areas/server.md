# Запуск, настройки и сервер

## Как устроен процесс

Один процесс, три части (`app.py` — единственное место, где создаются настоящие зависимости):
- **бот aiogram**: на Mac (`RUN_MODE=dev`) — polling, на сервере (`RUN_MODE=prod`) — webhook с секретом;
- **веб-сервер FastAPI**: вебхук Telegram, вебхуки Remnawave, уведомления платёжки, `/health`, `/status`;
- **фоновые задачи**: сводки тревог (1 мин), сверка с Remnawave (5 мин и при запуске), повторы выдачи (1 мин), проверка оплат (2 и 30 мин), сверка с платёжкой (09:00), доделывание возвратов (1 мин), сторож (1 мин), бэкап панели — присмотр (1 ч), бэкап базы (04:30, только prod), отчёт (10:00), пробные и ссылки после сбоя панели (1 мин).

При запуске бот проверяет версию панели: не та основная версия или неверный токен — тревога, 10 минут ожидания и **выход** (systemd перезапустит); панель недоступна — стартует с тревогой.

## Режимы

- `RUN_MODE`: `dev` (Mac, аккаунты `dev_<id>` в squad `test`) или `prod` (сервер, аккаунты `tg_<id>`).
- `PAYMENTS_MODE`: `platega`, `fake` (запрещён в prod), `off` (тарифы видны, купить нельзя, тревога при запуске).

| Логи с маскировкой | `logging_setup.py` |

| Веб-сервер и вебхук Telegram | `web/app.py`, `web/telegram.py` |

| Суммы текстом («150 ₽», «100 ⭐») | `content/amounts.py` |

Пути без `ops/` и `config/` — от `bot/src/tsproxy/`.

## Сервер

- Основной сервер — Axion (`ssh tsp`). Служба `tsproxy`, пользователь `tsproxy`. Код — `/opt/tsproxy/app`, `.env` — `/var/lib/tsproxy/.env` (600), база — `/var/lib/tsproxy/data/tsproxy.db`, бэкапы — `/var/backups/tsproxy`.
- Бот слушает адрес шлюза Docker-сети панели; снаружи — через туннель Cloudflare `bot.ts-proxy.com`.
- Сейчас `PAYMENTS_MODE=off`.
- **Любое действие на сервере — только после «ок» владельца на это действие.**

## Профиль бота в Telegram

Аватар, описание («Что умеет этот бот?» в пустом чате) и короткое описание («О боте» в профиле и в превью ссылки) бот ставит сам разовой командой — при запуске бота они не меняются. Тексты — `bot/content/client/bot_profile.yaml`, аватар — `bot/content/images/avatar.jpg` (Telegram берёт аватар только в .jpg). Код — `bot/src/tsproxy/bot/bot_profile.py`, команда — `bot/scripts/set_bot_profile.py`. Повторный запуск ничего не ломает: совпадающий текст не меняется, аватар ставится, только если его нет (каждая загрузка добавляет фото в историю аватаров).

Картинку описания в пустом чате через API поставить нельзя — только владелец в @BotFather. Сначала на тестовом @ts_proxybot, боевой — при выкатке.

1. В `bot/.env` — `BOT_TOKEN` нужного бота (для @ts_proxybot — тестовый).
2. `cd bot && uv run python scripts/set_bot_profile.py`. В конце — «Поставлено: …» или «Всё уже стоит».
3. Если написано «Аватар у бота уже есть — не трогали», а там старый аватар — запустить ещё раз с `--replace-avatar`.
4. Картинка описания: в Telegram открыть @BotFather → `/mybots` → выбрать бота → **Edit Bot** → **Edit Description Picture** → отправить файл `bot/content/images/description.png` (640×360). Если BotFather не берёт png — сохранить его как jpg и отправить снова.
5. Проверить: удалить чат с ботом (или открыть его с другого аккаунта) и открыть заново — до «Запустить» видны картинка описания и текст «Что умеет этот бот?» со ссылкой ts-proxy.com; в профиле бота — аватар и «О боте». Telegram может показывать старое несколько минут.
6. Поменять тексты — правка `bot_profile.yaml` и снова шаг 2.
