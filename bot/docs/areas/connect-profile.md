# Подключение, профиль и меню

Что клиент видит каждый день: меню, «Подключиться», «Мой профиль», «Мои устройства», инструкции. Пробный — [trial.md](trial.md), сроки и напоминания — [access.md](access.md).

## Правила

- **Живое меню**: нажатие кнопки присылает экран новым сообщением (чат поднимается в списке), а нажатое сообщение бот удаляет; старше 48 часов или уже удалено — снимает у него кнопки. `/start`, команды и уведомления тоже убирают прошлое меню: бот помнит последнее меню клиента в памяти (не в базе), после перезапуска старое меню уберётся при нажатии на нём. Сохраняемый текст (уведомления, сообщения об оплате, ответы поддержки, ссылка, присланная ботом сам) не удаляется — гаснут только кнопки. Какие фоновые сообщения становятся живым меню, а какие (рассылки, счёт в звёздах) прошлое не трогают — список в шапке `bot/delivery.py`. Счёт в звёздах сохраняет кнопку оплаты: Bot API не даёт её снять, старый счёт отсекает проверка перед оплатой. Уведомления, отправленные до выкатки метки, при нажатии удалятся как экран меню — принято. Правило живёт в `ClientDelivery` (`bot/delivery.py`). Команды: `/start`, `/profile`, `/buy`, `/support`, `/help` (список команд клиента; в группе администраторов `/help` — команды админки). Обработчики работают только в личном чате.
- **Строка статуса над главным меню**: «✅ Активна до …», «⛔ Закончилась», пробный — с датой (тот же статус, что в профиле). Меню спрашивает панель не дольше 3 секунд; нет прокси-аккаунта, панель не ответила или не успела — меню без строки, без ошибки и без тревоги.
- **Сутки простоя**: кнопка перехода по меню на экране, отправленном больше суток назад, открывает главное меню вместо нажатого экрана (старое убирается как обычно). Простой — по дате нажатого сообщения, ничего не хранится. Не касается действий («Подключиться», пробный, оплата, удаление устройства, перевыпуск) и кнопок уведомлений. Правило и список переходов — в `bot/menu.py`.
- **`/start` с параметром**: `?start=support` открывает поддержку (кнопки на сайте), `?start=devices` — «Мои устройства» (кнопка на странице подписки).
- **«Подключиться»** открывает страницу подписки `https://sub.ts-proxy.com/<код>`, есть кнопка «Скопировать ссылку». Прокси-аккаунт ищется по Telegram ID нажавшего.
- **Панель не ответила на «Подключиться»** — клиенту «ссылку пришлём сюда», и фоновая задача сама присылает экран подключения, когда панель ожила. Ждёт не дольше суток. В этом сообщении личная ссылка клиента — новое меню гасит только его кнопки. Тревога «Remnawave не отвечает» уходит администраторам.
- **Профиль**: статус словами, до какой даты и сколько осталось, «устройства N из 3», трафик — только у пробного.
- **Устройства**: список (модель, ОС, когда подключено) и «Удалить». Удаляется только устройство из списка нажавшего. Удаление лишь освобождает место: приложение с настройками может работать до обновления подписки.
- **«Перевыпустить ссылку»** — клиент сам, не чаще раза в сутки (по журналу событий; перевыпуск администратором попытку не расходует). Новая ссылка ломает подписку на всех устройствах — клиент добавляет её заново. Раньше суток кнопка на профиле и устройствах серая (Bot API `disabled`), в тексте — когда снова можно; старая или подделанная кнопка — отказ всплывашкой, экран не меняется.
- **Кнопки клиента — без смайликов** (смайлики — только со смыслом в тексте: ✅/⛔ в статусе, 🎁 в заголовке). Цвет (Bot API `style`) — в `BUTTON_STYLES` (`bot/screens.py`): «Подключиться» зелёная, «Удалить», «Перевыпустить ссылку» и «Да, перевыпустить» красные, остальные обычные. Кнопки админки не меняются.
- **Инструкции**: самая короткая выжимка на устройство, только Happ. Запасные приложения и скриншоты — на сайте: ссылка ведёт в раздел устройства `https://ts-proxy.com/help/<устройство>/` (на сайте это отдельные страницы). Шаг «Откройте вашу страницу подключения» — личная ссылка подписки нажавшего (панель спрашивается не дольше 3 секунд, пока ждём — «печатает…»); нет прокси-аккаунта, панель не ответила или не успела — «Нажмите „Подключиться“ → …», без ошибки и без тревоги.
- **Клиент заблокировал бота** — пометка, ему не шлём уведомления и рассылки; снимается при новом `/start`.
- **«Печатает…»**: пока бот ждёт панель или платёжку (подключение, инструкции, пробный, профиль, устройства, перевыпуск, счёт СБП и звёздами, «Проверить оплату»), у клиента в шапке чата «печатает…». Обработчик помечается флагом `TYPING`; ошибка отправки «печатает…» действие не ломает.
- **Ограничение частоты** нажатий на клиента — «ведро с жетонами» в памяти (`bot/throttling.py`).

## Где в коде

| Что | Файл |
|---|---|
| Меню, `/start`, инструкции | `bot/menu.py`, `bot/screens.py` |
| «Подключиться», ожидание ссылки | `bot/connect.py`, `services/connect_waits.py` |
| Профиль и устройства | `bot/profile.py`, `bot/profile_screens.py`, `services/profile.py`, `domain/profile.py` |
| Перевыпуск ссылки | `services/link_revoke.py`, `domain/link_revoke.py` |
| Запись клиента, «заблокировал бота» | `services/clients.py`, `bot/chats.py`, `bot/delivery.py` |
| Частота нажатий | `bot/throttling.py` |
| «Печатает…» при ожидании | `bot/chat_typing.py` |
| Обёртка Remnawave | `integrations/remnawave.py`, `integrations/remnawave_types.py` |

Пути — от `bot/src/tsproxy/`.

## Тексты

`bot/content/client/`: `menu.yaml` (меню, «О сервисе», ошибки), `connect.yaml` (подключение и инструкции), `profile.yaml` (профиль, устройства, перевыпуск), `buttons.yaml`, `commands.yaml`. Ссылки на приложения — `config/site.yaml`.
