# Бэкапы

Подробная инструкция по бэкапу базы бота и восстановлению — [../bot-backup.md](../bot-backup.md).

## Правила

- **Бэкап базы бота** — раз в сутки в 04:30 МСК, только в бою (`RUN_MODE=prod`): согласованная копия SQLite без остановки → `PRAGMA integrity_check` → gzip и шифрование `age` (открытый ключ тот же, что у панели) → `daily/` и `monthly/` (права 600) → файл в тему «💾 Бэкапы». Ежедневные хранятся 2 недели, месячные — 3 года.
- **Не получилась копия** — тревога, исключение для сторожа задач, старые копии не удаляются. **Не ушло в Telegram** — тревога, локальная копия остаётся.
- **Бэкап панели** делает скрипт `ops/remnawave-backup/remnawave-backup.sh` (cron, 04:00 МСК). Бот раз в час смотрит, есть ли копия моложе 26 часов и ушла ли последняя копия в Telegram (журнал скрипта). Проблема — одна тревога на проблему. Бот только читает журнал и список копий.
- Тексты тревог бэкапа базы бота — прямо в коде `jobs/backup.py` (исключение из правила «тексты только в content»).

## Где в коде

| Что | Файл |
|---|---|
| Бэкап базы бота | `jobs/backup.py`, `jobs/backup_files.py`, `jobs/age.py` |
| Присмотр за бэкапом панели | `services/panel_backups.py`, `domain/panel_backup.py`, `services/backup_copies.py` |
| Скрипт бэкапа панели | `ops/remnawave-backup/` (от корня репозитория) |

Пути — от `bot/src/tsproxy/`, кроме `ops/`.

## Тексты

Тревоги `panel_backup_*` — `bot/content/alerts/alerts.yaml`; строки отчёта — `bot/content/admin/report.yaml`.
